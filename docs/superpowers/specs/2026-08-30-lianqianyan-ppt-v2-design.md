# 《涟千言》产品说明 PPT V2 设计说明

## 1. 目标

基于 2026-08-30 最新《涟千言开发日志》、GraphRAG 设计与当前真实产品状态，重做一份 20 页创新赛道产品说明 PPT。

传播任务：让评委理解，涟千言不是增加了若干 AI 功能的聊天界面，而是一套以学习证据为核心、以课程约束 GraphRAG 为知识边界、能够持续给出下一步学习行动的个性化学习系统。

本轮采用“完整叙事重构”，不在旧稿上做名称与截图的局部替换。

## 2. 固定约束

- 输出格式为 PPTX，20 页，16:9，文件大小不超过 50MB。
- 对外品牌统一使用“涟千言”；角色名使用“小涟”，Live2D 角色素材可注明“昔涟”。
- 不出现学校、教师、单位名称。
- PPT 可见页面不放“AI辅助制作”标识；该标识由用户在佐证材料中处理。
- 不写“全自主 Agent Swarm”，不展示模型内部思维过程。
- 不伪造用户、成绩、学习画像、知识关系、来源、测试结果或产品运行状态。
- “未评估 ≠ 薄弱”“没有证据，不做假设”继续作为固定教育边界。
- GraphRAG 只描述为“课程约束 GraphRAG”，不宣称开放域实体发现、自动知识推理或自动修改掌握度。
- 长期记忆只用于账号级陪学上下文，不修改 Mastery、Diagnosis 或 Learning Evidence。
- MiniMax 是当前唯一语音输出路径；不再写 GPT-SoVITS、Genie-TTS 或浏览器朗读回退为当前能力。
- 所有页面都保留背景图；按章节使用多张粉紫蓝、青绿与深蓝的涟千言主题背景。

## 3. 叙事主线

新版 PPT 始终围绕一条学习闭环展开：

```text
真实学习行为
  → Learning Evidence
  → Mastery / Learner Profile
  → Diagnosis / Study Plan
  → 课程约束 GraphRAG 与知识星图
  → 小涟给出当前任务与下一步行动
  → 练习、复述、考试与资源学习
  → 新证据进入下一轮规划
```

五章结构：

1. 为什么做：P2–P3
2. 系统如何理解学习：P4–P8
3. 小涟如何推动下一步学习：P9–P16
4. 为什么它是一套可复用的 AI 教育系统：P17–P18
5. 我们真的把它做出来了：P19–P20

## 4. 页面设计

### P1｜封面

- 主标题：涟千言
- 副标题：面向个性化学习全过程的 AI 智能体学习空间
- 核心句：让 AI 不只回答问题，而是真正参与学习的发生。
- 保持简洁，使用角色与显化链环背景。

### P2｜学生缺少的是持续判断

- 说明普通工具解决“这道题怎么做”，真实学习还需要回答：哪里不会、先学什么、完成后计划如何变化、AI 是否理解当前状态。
- 结论：学习真正需要的是持续判断“我在哪里，下一步去哪”。

### P3｜涟千言把三件事连成一个系统

- 学习证据：理解学生当前状态。
- 课程约束 GraphRAG：理解知识位置与材料来源。
- 下一步行动：把理解转成任务、练习与重规划。
- 用一个简洁三段关系说明新版产品定位，不把能力写成功能清单。

### P4｜小涟串联完整学习闭环

- 学习目标 → 学习行为 → 学习证据 → 画像与诊断 → 规划 → 讲解/练习/复述/资源 → 评估 → 重规划。
- 强调小涟是统一交互入口，领域服务与工具在后台协同。

### P5｜Learning Evidence 是核心数据

- 展示 `learning_started`、`practice_answer_evaluated`、`exam_answer_evaluated` 的不同作用。
- 说明开始学习只记录行为；练习评价和已评分考试答案才更新掌握投影。
- 保留“没有证据，不做假设”“未评估 ≠ 薄弱”。

### P6｜六种掌握状态与六维画像

- 六种掌握状态：尚未评估、证据不足、薄弱、发展中、熟练、已掌握。
- 六维画像：总体掌握、画像可信度、证据覆盖、评估表现、证据深度、知识均衡。
- 未知维度显示“暂无”，不以 0 替代。
- 使用最新真实画像或诊断截图。

### P7｜诊断把状态转成学习任务

- 输入：Learner Profile、Diagnosis、当前课程与计划状态。
- 输出：知识点、行动类型、优先级、预计时间、诊断依据。
- 行动类型：ASSESS、REMEDIATE、STRENGTHEN、REVIEW。

### P8｜学生变化，计划动态重建

- 保留死锁示例，但明确为“示例链路”。
- Before：薄弱、重点补强；After：发展中、继续强化。
- 旧计划 SUPERSEDED，新计划 ACTIVE。
- 结论：练习结果是下一轮规划的起点。

### P9｜“下一步该学什么”常驻学习现场

- 展示真实数据驱动的三步引导：继续路线 → 弄懂薄弱点 → 留下证据。
- 小涟页左栏常驻下一步建议；资源工坊完成后给出看图谱、做自测、回路线的闭环出口。
- 强调没有可用计划或诊断时呈现诚实空状态。

### P10｜紧凑工作台、历史与长期记忆

- 展示最新小涟工作台：紧凑 Header、主对话、右下悬浮 Live2D、左侧会话与记忆。
- 账号级会话支持创建、切换、重命名、删除与消息持久化。
- 用户可保存或删除长期记忆；记忆只作为 Tutor 上下文。

### P11｜GraphRAG 回答受课程材料约束

- 用户问题 + 当前知识点 + 学习状态 → 词法检索种子 → 课程图谱一跳扩展 → 去重与重排 → Tutor → 带来源回答。
- `retrieval_mode` 使用 `graph_rag_course_grounded`。
- 说明关系来自既有课程材料，不自动推断学生掌握状态。

### P12｜知识星图让知识关系可以被探索

- 全量节点常驻，深色星空力导向布局。
- 支持平移、滚轮/双指缩放、节点拖动摆放、双击还原、适配全图。
- 节点用真实掌握状态着色；选中节点后高亮邻域并压暗其余。
- 使用最新知识星图真实截图。

### P13｜点击节点，直接进入章节正文与来源

- 知识点详情展示标题、章节大纲、章节正文摘录、掌握状态和材料来源。
- 详情数据来自 `/api/knowledge/points/{id}`；加载、错误、无来源均诚实呈现。
- 说明知识星图不是装饰图，而是进入课程内容和学习任务的导航界面。

### P14｜理解、练习、复述、考试与重规划

- 学习模块 → Tutor 讲解 → Practice → Reflection → Exam/Assessment → Replanning。
- 当前复述用于教学反馈，不直接修改 Mastery。
- 考试答案只有在自动评分或人工批阅完成后才进入证据投影。

### P15｜资源工坊是一条可验证的生成流水线

- 四阶段进度：生成学习材料 → AI 判断是否需要配图 → MiniMax 生成无文字隐喻插画 → AI 检查乱码、截断和占位符。
- 正文与图片可以并行；不需要配图时 `skipped:true` 且不消耗图片调用。
- 增强预览为主显示，Markdown 源码默认收起；支持富文本重点样式、AI 优化和 PPT 导出。
- 展示项目内置 6 页涟千言 PPT 模板作为产品能力证据，不把它作为整份比赛 PPT 的第二套模板。

### P16｜自然陪伴建立在明确的技术边界上

- Live2D 昔涟悬浮在工作台右下角，并随运行、思考与语音状态变化。
- 语音输入由浏览器识别并由用户确认发送。
- 语音输出只走部署方 MiniMax；失败时显示不可用，不静默回退。
- 技术目的是降低交流成本，不是增加装饰。

### P17｜Agent、Education Tools 与 MCP 共享教育能力

- Diagnosis、Planner、Tutor、Assessment 通过统一教育工具调用应用服务。
- Web、内部 Agent 和 MCP 共用 EducationToolRegistry，不复制业务规则。
- 典型工具：画像、诊断、当前计划、课程检索、学习证据、生成计划和重规划。
- 能力调用可验证，不展示模型内部思维过程。

### P18｜更新后的系统技术架构

- 表现层：React、TypeScript、Vite、Live2D。
- 应用服务层：FastAPI、Auth、Companion History/Memory、Resources。
- 智能能力层：Agent Orchestrator、课程约束 GraphRAG、Tool Registry、LLM、MiniMax Voice/Image、AnySearch。
- 教育领域与数据层：Learning Evidence、Mastery、Learner Profile、Diagnosis、Study Plan、Course Graph、SQLAlchemy/SQLite。
- 横向能力：MCP、来源追踪、安全边界、诚实降级。

### P19｜从 0 到 3.21，每一步都有开发证据

- Phase 1：基础前后端与认证。
- Phase 2：Evidence、Mastery、Profile、Diagnosis、Planner。
- Phase 3：Tutor、Agent、RAG、Dynamic Replanning、MCP。
- Product：工作台、Live2D、MiniMax、GraphRAG、知识星图、资源流水线、下一步闭环。
- 证据：Git Commit、开发日志、前后端测试、生产构建、浏览器实测、API 验证和问题追踪。
- 只使用日志中可复核的测试数量与运行证据，并注明对应阶段，避免把不同提交的统计口径混为一个总数。

### P20｜结束页

- 主标题：涟千言
- 主文案：让 AI 不只回答知识，而是真正参与一次学习的发生。
- 关键词：证据、理解、行动、成长。
- 结尾：每一次学习，都成为下一次成长的起点。

## 5. 视觉系统

- 继续使用用户认可的 6 张涟千言粉紫蓝主题背景，每页都有背景。
- P1–P3 使用粉蓝链环；P4、P7、P9、P11、P17 使用蓝紫学习空间；P5、P6、P8、P13 使用青绿证据光流；P10、P14–P16 使用紫粉陪伴光流；P18 使用深蓝技术网络；P19–P20 使用明亮收束背景。
- 吸收项目内置 PPT 模板的清晰标题、记号式章节、琥珀问答强调和页脚规则，但不把两套 PPT 模板混合为不一致的母版结构。
- 内容页降低整页白色蒙版，改用局部半透明内容承载区，让背景显化且不干扰阅读。
- 真实产品截图优先于抽象示意图；截图必须来自当前代码与真实数据状态。
- 每页只保留一个主结论。内容丰富通过信息层次、证据和讲述备注实现，不通过缩小字号或堆满卡片实现。

外部资料只用于解释技术背景时引用；产品能力、测试数量和运行状态以项目日志、代码和当前验证为准。

## 8. 验收标准

- 品牌、功能、技术边界与 2026-08-30 最新日志一致。
- 20 页叙事连贯，答辩时不会变成功能清单。
- 20/20 页存在背景图，且至少使用 6 种章节背景变体。
- 无旧品牌名称残留；无“AI辅助制作”可见标识；无学校、教师、单位名称。
- 无旧 TTS 当前能力、旧知识图谱截图或旧工作台截图。
- 无文字溢出、标题意外换行、截图拉伸、占位符残留或未解释的空白。
- PPTX 小于 50MB；LibreOffice 可打开并导出 20 页 PDF。
- 每页单独渲染检查，并完成全局 montage 复核。
