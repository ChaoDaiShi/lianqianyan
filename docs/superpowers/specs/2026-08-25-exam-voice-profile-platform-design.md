# EducationMind 考试、双向语音与成长画像设计

日期：2026-08-25

状态：用户已授权自主决策，设计自审通过并进入实现
目标版本：Phase 3-7

## 1. 目标

本阶段把 EducationMind 从“学习—练习—诊断”扩展为可闭环运行的学习评测平台：

1. 提供完整考试系统，支持自定义题型、自定义题目、组卷、发布、断点续答、服务端计时、自动保存、提交、自动评分、人工批阅与结果复盘。
2. 在现有浏览器语音输出上增加语音输入，并接入小涟对话、学习空间和考试文本作答。
3. 用真实掌握度、可信度、覆盖率和考试结果重构学生画像可视化，不生成虚假趋势。
4. 补齐容易被遗漏但直接决定可用性的能力：发布校验、答案隔离、试卷不可变、空态/错误态、结果导出、无障碍标签和不支持能力的诚实降级。

## 2. 现状与边界

- 前端为 React 18 + Vite + TypeScript，后端为 FastAPI + SQLAlchemy。
- 当前只有单一演示学习者，没有账号登录、教师角色或权限系统。
- `assessment` 路由只是骨架，尚无试卷、题库、作答和评分实体。
- 现有 `LearningEvidence` 与 `MasteryRecord` 已形成可信学习画像事实链。
- 现有语音能力只有浏览器端 TTS，没有麦克风输入。
- 当前画像页面有知识星图和文字卡片，但缺少维度对比、评测概览和数据充分性表达。

因此本阶段实现完整的单学习者考试业务与数据隔离，但不宣称已有多租户教师权限。命题工作台与学生考试接口分开；正式上线前仍需接入认证/角色授权。

## 3. 方案比较与决策

### 方案 A：纯前端 LocalStorage 考试

实现快，但无法提供可信计时、答案隔离、跨刷新恢复、服务端评分和画像证据。否决。

### 方案 B：允许任意 JSON Schema 或脚本定义题型

灵活度高，但验证、渲染、评分和安全边界不可控，容易引入脚本执行与不可复现评分。否决。

### 方案 C：安全题型模板 + 可配置评分策略 + 服务端状态机

采用该方案。创建者可以自定义题型名称、说明、作答形态与评分策略，但作答形态限制为经过验证的五类：单选、多选、判断、短答、长答；评分限制为精确匹配、集合匹配、关键词评分或人工评分。题目内容、选项、答案、关键词、解析、分值、难度和知识点均可自定义。

这一方案兼顾灵活性、可测试性和可信评分，且能与现有学习证据/掌握度投影集成。

## 4. 考试领域模型

### 4.1 实体

- `ExamQuestionType`：题型名称、说明、作答形态、评分策略、内置/自定义、归档状态。
- `ExamQuestion`：课程、知识点、题型、题干、选项、标准答案、关键词、解析、难度、默认分值、归档状态。
- `Exam`：课程、标题、说明、时长、及格线、是否随机题序、草稿/已发布/归档状态。
- `ExamQuestionLink`：试卷与题目的顺序及本卷分值。
- `ExamAttempt`：学习者、考试、进行中/待批阅/已评分状态、开始/截止/提交时间、得分与待批分值。
- `ExamAnswer`：作答、保存时间、自动/人工评分结果和反馈。

所有标识、时间和成绩由服务端生成。JSON 只用于受控的选项与答案值，不保存可执行表达式。

### 4.2 状态机

```text
试卷：draft ──publish──> published ──archive──> archived
作答：in_progress ──submit/expire──> needs_review ──manual grade──> graded
                         └──────────> graded（全部可自动评分）
```

- 草稿可编辑；发布前必须至少有一题、分值大于零且题目结构全部有效。
- 发布后的试卷、关联题目及结构型题型不可修改，避免历史作答语义漂移。
- 已发布考试才能开始作答；同一学习者再次进入时恢复未过期的进行中作答。
- 截止时间由服务端计算。保存或读取过期作答时自动结卷；前端倒计时只是提示，不是事实来源。
- 提交幂等，重复提交返回同一结果。

### 4.3 题型兼容矩阵

| 作答形态 | 允许评分策略 | 题目要求 |
| --- | --- | --- |
| `single_choice` | `exact` | 2–12 个唯一选项，单个标准答案 |
| `multiple_choice` | `set_exact` | 2–12 个唯一选项，至少一个标准答案 |
| `boolean` | `exact` | 布尔标准答案，不接收选项 |
| `short_text` | `exact` / `keyword` / `manual` | 精确答案、关键词或参考答案 |
| `long_text` | `keyword` / `manual` | 关键词或人工评分参考 |

关键词评分按命中的去重关键词比例给出透明部分分；人工评分在批阅前不计入已得分，并明确展示待批分值。

### 4.4 答案隔离

- 学生目录、开始作答、恢复作答和保存接口永不返回标准答案、关键词或解析。
- 只有提交后的结果复盘返回标准答案与解析。
- 命题接口与学生接口使用独立响应模型，防止同一模型误序列化答案。
- 当前项目无认证，因此仅承诺接口数据最小化，不声称命题接口已经具备角色级授权。

## 5. API 设计

命题与管理：

- `GET/POST /api/exams/question-types`
- `PATCH /api/exams/question-types/{id}`
- `GET/POST /api/exams/questions`
- `PATCH /api/exams/questions/{id}`
- `GET/POST /api/exams`
- `GET/PATCH /api/exams/{id}`
- `POST /api/exams/{id}/publish`
- `GET /api/exams/review-queue`
- `PATCH /api/exams/answers/{answer_id}/grade`

学生作答：

- `GET /api/exams/catalog?course_id=...&learner_id=...`
- `POST /api/exams/{id}/attempts`
- `GET /api/exams/attempts/{id}`
- `PUT /api/exams/attempts/{id}/answers/{question_id}`
- `POST /api/exams/attempts/{id}/submit`
- `GET /api/exams/attempts/{id}/result`
- `GET /api/exams/analytics?learner_id=...&course_id=...`

HTTP 语义：请求校验失败为 422；不存在为 404；状态冲突和发布后修改为 409；过期保存会先自动提交并返回 409；重复提交为 200 幂等成功。

## 6. 评分与学习画像联动

- 客观题与关键词题由纯函数评分器处理，可脱离 FastAPI 测试。
- 每道完成评分且关联知识点的答案只产生一次 `exam_answer_evaluated` 学习证据，来源为 `exam_system`。
- 掌握度投影使用该题实际得分比例、题目难度和是否满分；人工题只在人工批阅后投影。
- `ExamAnswer.evidence_id` 作为幂等标记，防止重复提交或重复批阅重复更新画像。
- 考试结果分析按已结卷记录实时聚合：考试次数、平均分、最佳分、通过率、客观题正确率、待批数量和按知识点表现。
- 画像可视化只展示数据库中已有的掌握度与考试结果；没有考试时明确显示“尚无考试记录”。

## 7. 双向语音

### 7.1 输出

保留现有 `speechSynthesis`：用户点击后朗读、中文音色优先、可停止、文字内容始终可见。

### 7.2 输入

新增 `useSpeechRecognition`：

- 能力检测使用标准 `SpeechRecognition`，兼容浏览器前缀 `webkitSpeechRecognition`；
- 每次仅在用户点击后启动，不自动申请麦克风权限；
- 默认 `zh-CN`、非连续模式、提供中间转写；
- 最终转写填入文本框，由用户确认后发送/保存，不自动提交答案；
- 明确区分监听中、处理中、权限拒绝、无语音、网络错误与不支持；
- 停止、错误、页面切换和组件卸载都释放识别实例；
- 音频不上传到 EducationMind 后端，实际处理边界由浏览器/系统语音服务决定并在 UI 标注。

接入位置：小涟对话、学习空间 Tutor、考试短答/长答。考试题干提供已有 TTS 朗读，但语音功能不改变考试计时。

## 8. 学生画像可视化

画像组件使用 React + SVG/CSS 原生实现，不引入重量级图表依赖：

1. `PortraitRadar`：掌握度、可信度、覆盖率、评测表现四维雷达。没有考试数据时评测维度标为“暂无”，不画成 0 分。
2. `EvidenceCoverageRing`：展示已评估/待评估知识点及可信度，使用可读文本作为无障碍等价内容。
3. `KnowledgePerformanceBars`：逐知识点对照当前掌握度与考试得分；没有考试样本时只显示掌握度。
4. `AssessmentSnapshot`：考试次数、平均分、最佳分、通过率、待批数量。
5. `PortraitNarrative`：继续保留小涟的阶段与建议，但结论必须可追溯到传入数据。

这些组件进入 `/archive` 成长画像页，诊断页补充考试数据入口；首页不重复堆叠复杂图表。

## 9. 前端信息架构

新增 `/exams`“考试中心”，包含四个页签：

1. 考试中心：已发布试卷、继续作答、结果入口。
2. 我的结果：历史成绩、待批状态、复盘和 JSON/CSV 导出。
3. 题库：自定义题型和题目管理。
4. 命题工作台：组卷、分值排序、发布校验与人工批阅队列。

学习星轨增加“考试中心”，移动端改为可横向滚动的固定底栏，保证每个入口触控宽度，不把七项压缩成不可点击的小格。

## 10. 错误、空态与可访问性

- 所有列表区分 loading、empty、error 和 ready；失败时不保留伪成功数据。
- 自动保存显示“保存中/已保存/保存失败”，离开前保留服务端最后成功时间。
- 每题有题号、分值、答题状态与可读 fieldset/legend；错误不仅靠颜色表达。
- 倒计时在最后五分钟进入警示，但不使用闪烁。
- 语音按钮具备动态 `aria-label` 和可见状态文字。
- 图表均提供标题、说明和文本化数值，不依赖 SVG 图形单独传达结论。

## 11. 明确不做

- 不实现摄像头监考、屏幕录制、面部识别或所谓 AI 作弊判定。
- 不执行用户自定义脚本、正则或代码作为评分逻辑。
- 不把浏览器语音识别描述为本地离线能力，也不保存原始音频。
- 不伪造多用户教师权限；本轮保持比赛演示单学习者边界。
- 不用生成图片替代可访问、数据驱动的 SVG 图表；当前设计系统已足以完成一致的视觉升级。

## 12. 验收门槛

- 后端评分器、状态机、幂等、计时、答案隔离、证据投影和 API 合同均有 pytest 覆盖，并使用临时数据库。
- 前端 API 映射、题型校验、考试展示、语音状态机、画像派生与导航均有 Vitest 覆盖。
- `pnpm test -- --run`、`pnpm check`、`pnpm build`、`uv run --project apps/api pytest -q` 全部通过。
- 浏览器实际完成：创建自定义题型和题目、组卷发布、开始作答、刷新恢复、语音填答、提交、查看结果、人工批阅、画像刷新。
- 浏览器控制台无新增错误，桌面和窄屏布局均可操作。
