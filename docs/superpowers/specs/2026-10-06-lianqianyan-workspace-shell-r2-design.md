# 涟千言 Workspace Shell R2 布局与字体优化设计

## 1. 目标

本轮在“证据星河”功能与视觉语言不变的基础上，重新校准桌面布局比例、字体层级、按钮尺寸、组件间距和结果阅读体验。重点解决左侧导航过窄、右侧工作区边界不清、正文和导航字号偏小、按钮规格不统一、长回答与来源信息阅读负担较高的问题。

不改变路由、账号、课程、数据模型、Agent SSE 协议、GraphRAG、语音、考试、工坊或历史持久化逻辑。移动端继续使用五槽 Dock；本轮不重新设计移动信息架构。

## 2. 当前基线

1440×900 实测：桌面导航宽 72px、导航标签 10px；主内容从 x=84 开始，内容最大宽度 1400px；首页主按钮 48px 高但字体仅 14px；部分首屏说明为 12px。小涟桌面工作区宽 1280px，左侧上下文列 272px，但正文、阶段标签、Trace 与来源多数仍为 9–14px。

这些尺寸在功能上可用，但在比赛展示、桌面长时间学习和高分辨率屏幕中显得偏轻，左侧导航和右侧主容器也没有形成稳定的两栏产品框架。

## 3. 方案比较

### 方案 A：只增大字体

改动最小，但 72px 导航无法容纳更大的标签，右侧容器比例问题仍然存在。字体放大后反而更容易拥挤。

### 方案 B：三级响应式工作区（采用）

移动端保持 Dock；中等宽度保持 84px 紧凑轨道；1280px 以上展开为 248px 完整侧栏。右侧内容区随侧栏切换缩进与最大宽度，同时统一字体、按钮和输出结果。这能在不改变业务结构的前提下形成清晰、稳定的桌面框架。

### 方案 C：可手动折叠侧栏

灵活性更高，但需要新增偏好状态、持久化和额外交互，超出本轮“布局和阅读性”目标。

## 4. 布局规格

### 4.1 桌面侧栏

- `md`（768–1279px）：84px 紧凑轨道，图标 22px、标签 11px；
- `xl`（≥1280px）：左边距 16px、宽 248px、顶部 76px、底部 20px的完整玻璃侧栏；
- 完整侧栏将入口分为“开始学习”“探索与训练”“记录与设置”三组；
- 每个入口高度 52–56px，图标 20–22px，主标签 14px，辅助说明 11px；
- 当前入口使用左侧渐变指示、浅紫底和清晰边框；
- 小涟入口保留品牌强调，但与其他入口保持相同网格和高度。

### 4.2 右侧工作区

- `md` 主内容左内边距为 104px；
- `xl` 主内容左内边距为 272px；
- 页面内容最大宽度提升到 1600px，并使用 `px-4 / sm:px-6 / lg:px-8 / xl:px-10`；
- 普通页面 section gap 为 24px，桌面大区块 gap 为 28–32px；
- 带 companion 的页面右侧辅助列从 20rem 调整为 22–23rem；
- 主容器始终 `min-width: 0`，避免长文本、代码块和知识图谱把工作区撑宽。

### 4.3 顶栏

顶栏维持全宽，用作全局身份与快捷操作。品牌主标题提高到 15px，副标题提高到 11px；账号与“小涟”快捷按钮高度、内边距与圆角统一。顶栏不与侧栏重复承载完整导航。

## 5. 字体层级

- 全局正文基准 16px，行高 1.65；
- `PageIntro` 标题：移动 30px、桌面 36px；说明：15–16px、行高 26px；
- 首页观察与正文：16px；指标标签不低于 12px；
- 侧栏主标签 14px、辅助说明 11px；
- 聊天正文：移动 15px、桌面 16px，行高 28px；
- Markdown H1/H2/H3：24/20/17px；列表与段落保持 15–16px；
- 流式阶段标签 11–12px；Agent Trace 主标签 13px，类型说明 10px；
- 来源标题 13px、摘录 13px，行高 21px；
- 不以 9px 作为主要可读信息字号，只允许极短的非关键英文标记使用 10px。

## 6. 按钮与控件

公共 Button 规格：

- default：高 44px、左右 20px、字体 15px；
- sm：高 40px、左右 16px、字体 14px；
- lg：高 52px、左右 28px、字体 16px；
- icon：44×44px；
- 按钮内部图标与文字间距统一为 8px；
- 同一区域的按钮保持同高，不再通过零散 `h-8`、`h-9` 形成视觉跳动，只有紧凑状态胶囊例外。

Input 和 Select 默认高 44px，Textarea 最小高度 104px；焦点环、边框和圆角继续使用现有品牌语义变量。

## 7. 输出结果优化

### 7.1 小涟回答

- 助手消息宽度在桌面限制为 86%，用户消息限制为 78%；
- 正文使用 16px / 28px；段落间距提升到 16px；
- 标题、列表、引用、代码块增加更明显的上下间距；
- 长代码块保持横向滚动，不扩大页面宽度；
- “朗读”“记住这条”和详情入口使用统一 40px 紧凑按钮或胶囊。

### 7.2 流式状态

- StreamingResponse 内边距从 16px 提升到 20–22px；
- 当前阶段标题 14px；状态节点不低于 11px；停止/重试按钮使用统一 sm 规格；
- 正文和最终 Markdown 使用同一字体与行高，避免生成中和完成后跳变。

### 7.3 Trace 与来源

- Trace 使用 24px 状态节点、13px 标签、10px类型说明；
- 来源卡标题和摘录增大到 13px；
- 结果详情的区块边距、分隔线和圆角统一，减少层层嵌套的小卡片感。

## 8. 测试与验收

- 测试先行覆盖：宽屏侧栏标记、分组与辅助说明；AppShell 的 md/xl 左内边距；PageIntro 字号；Button 尺寸；Markdown 与流式结果字号；
- `pnpm check`、完整 Vitest、生产构建；
- 使用真实账号在 1440×900、1280×800、1024×768、390×844 检查布局；
- 记录侧栏宽度、主内容起点、按钮高度、正文计算字号和横向溢出；
- 首页、小涟、知识空间、工坊与设置至少各检查一次；
- 最终浏览器要求 console、page error、request failure 和 HTTP 4xx/5xx 均无本轮回归。
