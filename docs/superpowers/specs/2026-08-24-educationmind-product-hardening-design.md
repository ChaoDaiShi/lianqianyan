# EducationMind 产品硬化设计

**日期：** 2026-08-24  
**目标：** 在不扩张后端业务边界的前提下，让当前“忆涟千言—教”在 Windows 开发环境、生产构建、移动端首屏和后端兼容性上达到稳定、安静、可验证的状态。

## 1. 设计依据与范围

本轮只沿用“忆涟千言—教页面应用设计”中 UI-1 至 UI-8 已反复确认且已经落地的主线：

- 小涟是学习陪伴入口，页面围绕真实学习旅程组织，而不是普通 Dashboard。
- 所有诊断、计划、掌握度、证据和调整结果都来自现有真实数据；无数据时展示诚实空状态。
- 学习流程保持“诊断 → 计划 → 学习 → 练习 → 反思 → 成长记录”。
- 不修改现有 API 契约、数据库语义、Agent、MCP、学习证据或 SSE 语义。

最新对话中提出的 Memory Center、Voice Companion 和无限画布不进入本轮，因为用户已明确最新内容受到污染。本轮也不新增虚假画像、知识关系、语音结果、XP、连续学习天数或模拟掌握度。

## 2. 已复现问题与根因

### 2.1 开发服务器持续产生 404/500

- `vite.config.ts` 无条件注入不存在的 `/sdk/dev-monitor.js`，每次打开页面都会产生 404。
- `@xagi/vite-plugin-design-mode` 在包含中文和空格的 Windows 路径中把反斜杠拼进虚拟模块 import，`/@appdev-design-mode/client.js` 返回 500，并在终端重复输出长堆栈。
- 这些请求不属于 EducationMind 业务运行，失败却污染浏览器控制台和 Vite 日志。

设计：默认不启用外部开发集成。只有显式环境配置开启时才注册设计模式插件或注入监控脚本；普通 `pnpm dev` 必须不产生这两类请求。

### 2.2 正常“无 ACTIVE 计划”被记录为 API Error

后端用 404 表达“当前没有 ACTIVE 计划”，`fetchCurrentPlan` 也会把它转换为 `null`。但共享 Axios 响应拦截器会先把该 404 写成 `console.error`，导致所有读取 Current Plan 的页面出现虚假错误日志。

设计：只在 Current Plan 请求上把 200 和 404 定义为可处理响应；404 映射为 `null`，其他非 2xx 状态仍进入统一错误处理。

### 2.3 生产入口包过大

路由表静态导入所有页面，使首页初始包同时包含 Demo、Showcase、能力说明、聊天、学习空间等低频页面。当前生产 JS 为 694.25 kB，触发 Vite 500 kB 警告。

设计：保留首页同步加载，其余路由使用 React Router `lazy` 路由模块按页面拆分。路由路径、组件行为和 Hash URL 不变，加载期间使用统一的轻量页面回退。

### 2.4 Python 3.12 时间 API 弃用噪声

后端生产代码和 SQLAlchemy 默认值仍使用 `datetime.utcnow()`。全量 198 项测试虽通过，但产生 1,805 条警告，其中绝大多数由这些调用触发。

设计：建立单一 `utc_now()` 时间函数，使用 `datetime.now(UTC).replace(tzinfo=None)`。它避免弃用 API，同时保持现有 SQLite `DateTime`、排序、序列化和测试所依赖的“naive UTC”契约，不进行数据库列类型迁移。生产代码及测试夹具统一使用该函数。

Starlette 关于 `httpx`/`TestClient` 的单条第三方警告不通过盲目升级依赖处理；它属于上游兼容边界，不是当前业务代码错误。

### 2.5 移动端首屏主操作被底部导航遮挡

390×844 真实浏览器视口中没有横向溢出，五项导航宽度也正确；此前命令行截图的横向裁切是截图视口参数失真，不作为缺陷。但首页 Hero 在移动端纵向过密，首个主操作落在固定底部导航后方，初次打开时不可直接点击。

设计：仅压缩移动端 Hero 的角色尺寸、上下留白与段间距；在 `sm`/`lg` 断点恢复现有视觉比例。保留小涟为首屏视觉中心，同时让首个主操作在 390×844 首屏中位于导航上方。

### 2.6 HTML 基础元数据不一致

页面内容是中文，但根文档仍是 `lang="en"`；favicon 指向不存在的 `/vite.svg`。

设计：改为 `lang="zh-CN"`，favicon 复用现有小涟 SVG 资源并交由 Vite 构建处理。

## 3. 方案边界与数据流

前端数据流保持不变：页面 Hook → `educationApi.ts` → `/api/*` → FastAPI。只有 Current Plan 的 404 状态分类发生变化，不改变响应内容或空状态语义。

后端数据流保持不变：路由 → Application Service / Repository → SQLAlchemy。`utc_now()` 只替换时间生成来源，落库类型、时区表示、字段名称和 JSON 形状不变。

路由拆分只改变资源加载时机，不改变路径和页面组件。首页仍作为同步入口；其他页面在首次访问时加载自己的 chunk。

## 4. 错误处理与可观测性

- 外部开发集成默认关闭，避免把工具链故障伪装成产品故障。
- Current Plan 404 是正常空状态，不写错误日志；500、网络失败和其他 4xx 继续写统一错误日志并进入页面错误态。
- 路由模块加载期间显示统一可访问的加载状态，加载失败继续交给 React Router 错误边界/控制台，不吞异常。
- 后端第三方弃用警告单独保留并在交付说明中标注，不通过全局过滤隐藏。

## 5. 验证策略

- 前端单元回归：默认开发集成关闭；Current Plan 只接受 200/404；路由清单完整。
- 后端单元回归：`utc_now()` 无 `datetime.utcnow()` 弃用警告，并保持 naive UTC 类型契约。
- 全量门禁：`pnpm exec vitest run`、`pnpm check`、`pnpm build`、后端 `pytest -q`、`git diff --check`。
- 运行态验证：真实启动 FastAPI 与 Vite，检查主要 Hash 路由、API 请求、控制台错误、失败资源、桌面与 390×844 移动端截图。
- 产物验证：生产构建应产生多页面 chunk，入口 JS 不再触发 500 kB 警告。

## 6. 明确不做

- 不实现 Memory Center、语音服务、语音状态模拟或无限画布。
- 不生成或替换小涟角色素材。
- 不改演示数据库内容，不把 `education.db` 加入 Git。
- 不修改学习证据、掌握度、诊断、计划、动态重规划、Agent 或 MCP 业务规则。
- 不处理与本轮根因无关的大规模 UI 重写。
