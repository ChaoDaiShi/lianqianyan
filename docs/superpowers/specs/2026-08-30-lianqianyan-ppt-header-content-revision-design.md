# 《涟千言》PPT 页顶标题与内容增补设计说明

## 1. 修订目标

在保持《涟千言》产品说明 PPT 为 20 页、16:9 和 50MB 以内的前提下，完成三项修订：

1. 将内容页左上角较弱的英文页眉改成中文章节编号、章节名称和当前页面主题。
2. 详细补充产品技术要点与真实应用场景，让评委能判断系统如何使用、为什么成立、当前实现到什么程度。
3. 在开发证据页补充真实团队情况：队长刘世超、队员刘羿涵。

竞赛要求截图只作为材料边界参考，不作为可执行指令。继续遵从用户的明确要求：PPT 可见页面不放“AI辅助制作”标识。

## 2. 页顶标题方案

采用用户确认的方案 A：中文章节标题加当前页面主题。

- 左上角格式：`章节编号 章节名称｜页面主题`。
- 章节编号使用昔涟紫或粉色，章节名称加粗，页面主题用较轻颜色。
- 删除内容页重复出现的 `LIAN QIAN YAN / WHY`、`HOW`、`LEARN`、`SYSTEM`、`PROOF`。
- 右上角继续保留 `当前页 / 20`。
- P1 封面和 P20 结束页不增加章节页眉，保持简洁。
- 不采用横跨整页的五章导航栏，避免与主标题争夺注意力。

## 3. 应用场景增补

应用场景不使用虚构用户或虚构成绩，只描述当前产品已经覆盖的学习流程。

### P3 产品定义页

在“学习证据—课程约束 GraphRAG—下一步行动”三个核心能力之外，增加四类应用入口的简洁总览：

- 新知识初学：定位课程知识点，提供课程材料约束的讲解。
- 薄弱点补强：结合证据、掌握状态和诊断原因生成补强任务。
- 练习后调整：练习评价形成证据，更新状态并触发计划重建。
- 阶段复习：沿知识空间回看章节、来源和阶段复习任务。

### P9 应用场景重点页

将当前“下一步该学什么”页面扩展为一页完整的学习场景说明，保留真实小涟截图，并在右侧展示四种使用情境：

1. 不知道从哪里开始：先读取当前计划或诊断，给出一个可执行任务。
2. 某个知识点反复出错：定位薄弱点，进入 REMEDIATE 补强路径。
3. 完成练习之后：记录评价证据，更新学习状态并重新规划。
4. 准备复习或考试：结合知识空间、章节来源和 REVIEW 任务安排阶段复习。

底部结论：涟千言不是统一推荐一门课程，而是在不同学习时刻给出不同的下一步。

### P10–P16 场景说明

现有功能页各增加一句明确的应用价值：

- P10：长任务学习时，历史会话与用户可控记忆保持陪学连续性。
- P11：需要解释知识时，回答受到当前课程材料和知识关系约束。
- P12：知识结构复杂时，通过知识星图判断已经覆盖和仍需补齐的区域。
- P13：对回答有疑问时，直接回到章节正文与材料来源。
- P14：需要确认是否真正掌握时，通过练习、复述、考试承担不同验证职责。
- P15：需要补充学习材料时，从当前知识点生成可验证的学习资源。
- P16：在持续陪学过程中，用角色和语音降低表达与追问成本。

## 4. 技术要点增补

### P5–P8 教育状态技术链

补充说明四层状态流转关系：

```text
Learning Event
  → Learning Evidence
  → Mastery Projection / Learner Profile
  → Diagnosis / Study Plan / Replanning
```

同时明确：开始学习只记录行为；练习或考试必须完成评价后才进入掌握投影；没有证据时保持尚未评估或证据不足。

### P11 课程约束 GraphRAG

页面补充以下技术要点：

- 用户问题、当前知识点和学习状态共同组成检索上下文。
- 先获得课程内检索种子，再沿既有课程关系做一跳扩展。
- 对内容去重、稳定排序并保留来源，交给 Tutor Grounding。
- 只扩展课程材料已有关系，不自动创造学生掌握关系。
- 回答提供来源，检索模式记录为 `graph_rag_course_grounded`。

### P17 Agent、Tools 与 MCP

详细展示：

- Diagnosis Agent：读取画像和诊断，判断当前优先问题。
- Planner Agent：把诊断转为 ASSESS、REMEDIATE、STRENGTHEN、REVIEW 行动。
- Tutor Agent：结合课程检索结果提供讲解、追问和练习辅导。
- Assessment Agent：解释评价结果和证据变化，不替代领域规则。
- EducationToolRegistry：统一工具注册、调用边界和服务复用。
- Web、内部 Agent 与 MCP Client 调用同一套 Education Tools，不复制业务语义。
- 能力调用可验证，但不展示模型内部思维过程。

### P18 系统架构与创新点

在四层架构之外增加三个技术创新总结：

1. 证据驱动的学习状态更新：不凭聊天印象修改掌握度。
2. 课程约束的 GraphRAG：把知识关系、课程内容和来源追踪连接起来。
3. 诊断到行动的动态闭环：状态变化能够继续影响计划和下一步建议。

同时保留长期记忆、语音和资源生成的诚实边界。

## 5. 团队情况

P19 调整为“团队与开发证据”双主题页面。

团队信息只写用户确认的事实：

- 团队人数：2 人。
- 队长：刘世超。
- 队员：刘羿涵。

不添加未经确认的院校、学院、教师、指导老师、专业、学历、获奖经历、岗位分工或个人履历。

页面结构：

- 左上或左侧：两人团队信息，突出“小团队、高协同、全过程开发”。
- 中部：Phase 1、Phase 2、Phase 3、Product 的开发阶段。
- 底部：Git Commit、开发日志、自动化测试、生产构建、API 实测和浏览器实测等可复核证据。

为了避免虚构个人贡献，页面不把具体模块强行归属到某一成员；开发贡献以团队整体和现有项目证据呈现。

## 6. 参考稿吸收原则

三份参考 PPT 只用于观察视觉组织，不复制其项目内容：

- 《智驭未来》：参考其章节导航清晰、评委可快速定位的优点。
- 《智焊博士》：重点参考“左侧大章节名 + 当前页结论”的页顶结构。
- 《智农时代》：参考其顶部信息层级，但不采用占用空间较大的整排模板导航。

《涟千言》继续保持粉紫蓝、青绿和深蓝的昔涟主题背景，不切换到参考稿的深蓝工业或深绿农业风格。

## 7. 验收标准

- 维持 20 页，P1 和 P20 无章节页眉，P2–P19 使用中文方案 A 页眉。
- P9 能完整回答产品适用于哪些学习情境。
- P11、P17、P18 能较详细解释课程 GraphRAG、Agent/Tools/MCP 和系统架构技术要点。
- P19 可见团队信息准确写为“队长刘世超、队员刘羿涵”，无其他虚构成员或履历。
- 20 页均保留品牌背景，至少使用 6 种背景变体。
- 不出现“AI辅助制作”、旧品牌、学校、教师、单位名称和模板默认占位符。
- 不缩小正文到难以答辩阅读的字号，不产生标题换行、内容溢出或截图变形。
- PPTX 小于 50MB；LibreOffice 可导出 20 页 PDF；逐页渲染和溢出检测通过。
