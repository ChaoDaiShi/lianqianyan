# 涟千言“证据星河”学习空间 V2 设计说明

## 1. 目标与边界

本轮把涟千言从“功能齐全但视觉与反馈偏平”的教育工具，升级为以真实学习证据为主线的陪伴式学习空间。改造同时覆盖核心视觉、首页信息架构、小涟对话、Agent 过程透明度、流式输出、响应式导航和公共表单组件，并通过真实账号、真实后端和浏览器完整走查验证。

项目继续使用 React 18、Vite、TypeScript、Tailwind、FastAPI、SQLAlchemy 与现有 Provider 抽象；不增加新的前端框架，不迁移状态管理，不伪造学习数据，不改写账号与课程范围模型，不引入数据库迁移。`EducationMind` 与 `EDUCATION_*` 只在兼容性要求的位置保留，对外品牌仍为“涟千言”。

## 2. 现状审计

本次审计覆盖路由注册、24 个页面与页面测试文件、布局与设计组件、前端 API 客户端、Agent 编排、Tutor 服务、课程知识检索、历史记录与长期记忆、项目架构文档和最近的 GraphRAG 设计计划。浏览器使用本地调试账号遍历首页、我的学习、诊断、知识空间、考试、工坊、档案、设置、小涟和关于页，并在 1440×900 与 390×844 两个视口检查页面。

确认的问题：

1. 首页首屏以大面积背景和人物留白为主，真实学习状态只占较小区域，诊断、计划、任务、证据之间的关系没有形成可一眼理解的视觉结构。
2. 公共 `Button`、`Input`、`Textarea`、`Select` 仍保留模板的蓝灰色与小圆角，和涟千言的紫、天蓝、柔粉玻璃体系不一致，造成页面局部风格断裂。
3. 移动端主导航依靠横向滚动容纳八个入口，最后几个入口默认不可见；小涟入口不在主导航中，品牌最重要的陪伴能力反而需要从顶部次级入口进入。
4. `src/lib/services.ts` 已包含通用 SSE 客户端，但后端没有业务流式接口，小涟调用 `/api/agents/chat` 后只能整段等待。Agent、工具、课程检索和来源信息均在回答完成后折叠显示，用户在等待期无法判断系统正在做什么。
5. 小涟工作区在移动端把历史、记忆、下一步和聊天纵向全部展开，首条消息需要较长滚动才能到达；桌面端虽然信息完整，但缺少清晰的“当前思考路径”和答案生成态。
6. 现有 `XiaolianDailyInsight` 已实现真实诊断、最近证据与下一步建议，却没有挂载到首页，导致已完成的业务信息没有形成可见价值。
7. 当前页面大量各自写死浅色背景、边框和输入样式，暗色主题通过长列表覆盖工具类维持兼容，新增页面容易继续扩大样式漂移。

开发服务在跨会话后由工具环境回收而出现的 `ERR_CONNECTION_REFUSED` 属于本地运行进程生命周期，不作为产品缺陷。重启 Vite 后复查，页面本身无横向文档溢出；移动导航仍存在默认可见性和入口优先级问题。

## 3. 方案比较与选择

### 方案 A：只做视觉润色

统一颜色、圆角、阴影并调整间距，改动小，但不会解决首页信息弱、Agent 等待黑盒和移动导航优先级问题。它只能让旧结构更精致，不能体现产品创新。

### 方案 B：证据星河学习空间（采用）

保留现有领域模型和路由，将“证据 → 诊断 → 计划 → 学习 → 验证”变成统一的视觉与交互叙事。首页用动态 SVG 证据轨道呈现当前闭环，小涟用 SSE 把真实 Agent 阶段和答案增量展示出来，公共壳层与控件同步升级。该方案能在可控改动内同时增强产品辨识度、过程可信度与实际可用性。

### 方案 C：重做全站信息架构

重新组织全部路由、课程模型和页面层级，想象空间最大，但会引入大范围迁移与回归风险，也会偏离本轮“优化现有完整产品”的目标。

## 4. 产品概念与创新点

### 4.1 证据星河

学习不是一组静态百分比，而是一条由真实行为点亮的轨道。首页的 SVG“证据轨道”包含诊断、计划、学习、验证四个节点：完成节点显示实心光点，当前节点显示脉冲环，等待节点保持低饱和轮廓。中心显示今天的核心知识点或“等待首次诊断”，环外只展示真实证据数量、当前任务数量与学习闭环进度。

轨道不会伪造掌握度或完成状态。其状态完全由 `DiagnosisResult`、当前 `PersistedStudyPlan`、任务与 `LearningEvidence` 推导。

### 4.2 可见的 Agent 思考路径

小涟对话新增“协作流”反馈。请求开始后依次显示：理解问题、读取学习证据、检索课程知识、调用能力、组织回答。后端只在真实步骤发生时发送事件；工具失败显示失败状态，未执行的步骤不出现。

过程呈现的是可审计的执行阶段与来源，不展示模型隐含推理或伪造思维链。最终答案继续保留 Provider、模型、课程来源、建议动作与 Agent/Tool Trace。

### 4.3 双层流式体验

SSE 流同时承载过程事件与答案增量：

- `status`：当前阶段及用户可读说明；
- `trace`：已完成或失败的 Agent/工具节点；
- `delta`：答案文本增量；
- `result`：完整响应元数据与最终答案；
- `error`：可公开的错误信息；
- `done`：流正常结束。

即使上游 Provider 只返回完整文本，服务端也以明确的传输分块逐步交付最终文本；`response_mode` 仍诚实标记 `provider` 或 `fallback`，不会把基础辅导伪装为云模型输出。旧 `/api/agents/chat` 保留兼容。

### 4.4 行动闭环

首页、今日观察、小涟回答和底部移动导航共享同一条行动语义：用户始终能看到“现在最重要的一步”、为什么推荐、完成后会留下什么证据。建议动作不只作为文字列表出现，而是映射到现有诊断、计划、学习空间、考试和工坊入口。

### 4.5 品牌 SVG 语言

新增代码原生 SVG 品牌标记和证据轨道：以两条交织的水纹轨迹、四个证据节点和星点构成“涟”与“千言”的视觉隐喻。SVG 使用 `currentColor`、渐变和可访问标题，可在顶部栏、移动 Dock、空状态和 Figma 设计稿中复用，不增加位图依赖。

## 5. 视觉系统

视觉风格称为“柔光星河”。它延续现有紫色 `#8B7CF6`、天蓝 `#6CA8FF`、柔粉 `#FF9FCB` 与深墨色 `#29234A`，强化以下规则：

- 页面底色使用低对比极光渐变，核心工作区使用半透明白色/深色玻璃面；
- 主要面板圆角 28–32px，控件圆角 14–18px，行动按钮采用胶囊形；
- 只给当前行动、运行节点和品牌轨道使用发光效果，普通卡片降低阴影，避免全页“漂浮”；
- 标题继续使用 Inter、苹方/微软雅黑系统回退，中文标题采用紧字距，正文保持 1.65–1.8 行高；
- 状态颜色除色相外必须同时包含图标、文字或线型，不以颜色作为唯一信息；
- `prefers-reduced-motion` 下关闭轨道脉冲、位移和流光，保留静态状态。

公共 `Button`、`Input`、`Textarea`、`Select` 改为语义品牌样式，页面局部可继续通过 `className` 覆盖尺寸，不再默认出现模板蓝色。

## 6. 页面设计

### 6.1 全局壳层

桌面端保留左侧学习轨道，但增强当前项、分组与小涟入口；顶部栏使用新的 SVG 品牌标记、当前账号和小涟快捷入口。移动端改为五槽 Dock：`首页`、`我的学习`、中央突出的小涟入口、`知识空间`、`更多`。更多面板提供诊断、考试、工坊、档案和设置，所有入口无需横向滚动即可发现。

### 6.2 首页

首屏从“大人物 + 文字”改为双栏学习指挥台：

- 左栏：问候、当前观察、唯一主行动、推荐原因与三项真实状态；
- 右栏：证据星河 SVG、小涟小尺寸陪伴形象、当前阶段和闭环完成度；
- 下方：更紧凑的今日路径，随后挂载 `XiaolianDailyInsight`，展示当前关注、最近证据和下一步。

没有诊断、计划或证据时展示诚实空状态，但仍给出可执行的第一步。

### 6.3 小涟工作区

桌面端采用 17rem 上下文栏 + 可伸缩对话主区。历史、长期记忆与下一步仍在左栏；移动端收敛为可展开的“对话与记忆”上下文条，聊天和输入框优先出现在首屏。

对话主区包含：

- 会话标题、服务状态和当前知识上下文；
- 消息流；
- 流式回答卡，内含可见阶段、增量正文、停止按钮与光标；
- 完成后的来源、Trace、朗读、记忆和建议动作；
- 底部粘性输入区与快捷问题。

请求失败时保留用户问题和已收到的部分正文，显示重试动作；取消时标记“已停止”，不写入助手历史。只有收到完整 `result` 后才保存助手消息。

## 7. 代码结构

### 前端

- `src/components/brand/LianMark.tsx`：品牌 SVG；
- `src/components/home/EvidenceOrbit.tsx`：证据轨道 SVG 与纯函数状态模型；
- `src/components/xiaolian/StreamingResponse.tsx`：流式阶段与正文呈现；
- `src/lib/agentStream.ts`：SSE 事件解析、URL 解析、取消和错误归一化；
- `src/pages/XiaolianPage.tsx`：消费流并管理草稿消息；
- `src/components/layout/LearningRail.tsx`：桌面轨道与移动 Dock；
- `src/components/home/HeroBanner.tsx`、`src/pages/Home.tsx`：学习指挥台与今日观察；
- `src/components/ui/*`、`src/design/theme.css`：公共控件和语义视觉收敛。

### 后端

- `apps/api/app/agents/base.py`：流式事件模型；
- `apps/api/app/agents/orchestrator.py`：可选事件接收器，在真实步骤完成时发送状态/Trace；
- `apps/api/app/api/routes/agents.py`：新增 `/api/agents/chat/stream`，使用 `StreamingResponse` 输出标准 SSE；
- 原 `/api/agents/chat` 与所有现有响应模型保持兼容。

## 8. 数据流与安全

1. 前端提交与普通 Agent Chat 相同的账号、学习者、课程、线程与能力范围。
2. 后端在创建流之前完成账号、学习者、课程与线程归属校验；校验失败仍返回常规 4xx，不进入 SSE。
3. 通过后，路由启动编排任务并消费有界异步队列。编排器把公开阶段与 Trace 放入队列，最终返回现有 `AgentsChatResponse`。
4. 路由把答案按 Unicode 安全片段发送为 `delta`，再发送完整 `result` 和 `done`。
5. 浏览器使用 HttpOnly Cookie 与 `credentials: include`，支持 `AbortSignal`；错误正文不包含上游密钥、Base URL、内部堆栈或数据库路径。
6. 历史记录仍由现有 Companion API 持久化；用户消息先保存，助手消息只在完整结果到达后保存。

## 9. 测试与验收

采用测试先行：

- 后端先增加失败测试，证明 SSE 顺序、Trace 真实性、完整结果、认证范围和错误清理；
- 前端先增加失败测试，证明事件解析、增量合并、取消、错误保留、移动 Dock 和 SVG 状态映射；
- 组件测试覆盖无数据、部分数据、完整闭环和 reduced-motion；
- 运行 `pnpm check`、前端相关 Vitest、后端相关 Pytest 和生产构建；
- 使用真实本地后端、正式账号流程与 Chrome 验证：首页、流式对话、来源详情、历史保存、取消、桌面/移动布局、刷新会话；
- 留存改造前后截图、浏览器错误与失败请求清单；
- Figma 文件必须保留可编辑文字、组件、变量和 SVG 层，网页捕获只用于布局对照，完成后删除捕获根节点。

## 10. 完成标准

1. 首页在桌面和移动端首屏内呈现当前行动、证据轨道和可解释原因，不再以大面积无信息留白为主。
2. 小涟请求期间可见真实阶段，答案逐段出现，可取消；结束后历史、来源、Trace、Provider 和建议动作一致。
3. 移动端五槽 Dock 默认可发现小涟与更多入口，无主导航横向滚动。
4. 公共表单控件与品牌风格一致，暗色模式、键盘焦点和 reduced-motion 可用。
5. 不生成虚假诊断、计划、证据、来源或 Agent 节点；所有空状态和降级状态如实说明。
6. 现有核心路由、账号、课程选择、语音、GraphRAG、考试、资源、档案和设置能力不回退。
7. 自动检查、生产构建、后端聚焦测试和真实浏览器验收通过，工作区只包含本轮有意变更。
