# EducationMind 登录与验证码恢复设计

## 背景与根因

当前账号版认证链路包含两个相互独立的问题：

1. Cloudflare Turnstile 是一次性 token。前端在登录或注册失败后仍持有旧 token，也没有调用 widget reset；下一次提交会继续携带已经被服务端拒绝或已过期的 token，用户无法自动获得一次新的验证机会。
2. API 默认数据库 URL 为 `sqlite:///./education.db`。SQLite 的相对路径以 API 进程工作目录为基准。仓库现有 `education.db` 与 `apps/api/education.db` 的账号数据不同，因此从不同目录手动启动 API 会造成注册和登录使用不同账号库的现象。

## 目标与边界

目标：

- 登录或注册失败后，自动丢弃旧验证码 token 并 reset Turnstile；用户名、显示名称和密码继续保留。
- 统一默认 API 数据库的解析基准，避免 API 工作目录变化导致账号库切换。
- 保留现有安全边界：服务端继续强制校验 Turnstile（已配置时）、不自动创建账号、不绕过密码校验、不覆盖任何现有 SQLite 数据。
- 用前后端自动化测试覆盖回归行为，并完成前端静态检查、构建和认证 API 烟测。

不在本次范围内：

- 数据库合并、账号迁移或猜测哪一份 SQLite 才是用户希望保留的数据。
- 修改密码找回、账号解锁后台或新增第三方登录。
- 把失败请求静默重试为成功；验证码重置后仍需用户完成新的挑战并再次提交。

## 方案比较

### 方案 A：只在前端失败后 reset Turnstile（采用）

让 widget 提供受控的 reset 回调，认证操作拒绝时由页面清空 token 并触发 reset。后端只维持现有认证契约；默认 SQLite 路径则解析到 `apps/api` 配置文件所在目录，避免工作目录差异。

优点是改动小、不会重复提交密码、能覆盖真实的一次性 token 生命周期；失败原因仍由后端决定。缺点是用户仍需完成新的 Turnstile 挑战并主动再次提交。

### 方案 B：前端在失败后自动重新提交

失败后自动 reset、等待新 token 并再次调用登录/注册。

这会自动重复密码认证请求，容易放大错误、锁定计数和网络故障，也不能保证新 token 已经获得，因此不采用。

### 方案 C：后端接受旧 token 或取消已配置环境的强制校验

可以消除表面上的重复验证，但会削弱 Turnstile 的安全边界，并无法解决错误数据库导致的历史账号不可见问题，因此不采用。

## 组件与数据流

认证页面持有表单字段与当前 token。`TurnstileWidget` 负责加载脚本、渲染 widget、向页面报告 token/过期/错误，并通过 ref 暴露 `reset()`。页面提交认证请求时保留现有字段；认证 Promise rejected 时，页面清空 token 并调用 widget reset。模式切换也沿用同一 reset 逻辑。账号错误只显示错误文案，不清空字段。

API 启动时由 `Settings` 将默认相对 SQLite URL 解析为基于 `apps/api` 目录的稳定 URL；显式的 `EDUCATION_DATABASE_URL`（尤其是生产绝对路径）保持原样。测试使用临时数据库覆盖环境变量，确保不会触碰工作区 SQLite。

## 错误处理

- Turnstile 400：显示人机验证失败提示，清空旧 token，重新渲染/重置 widget。
- 用户名或密码 401、账号锁定 423、用户名冲突 409：显示对应现有提示，清空旧 token并 reset，以便下一次认证使用新 token；不清空表单。
- 网络或服务端未知错误：显示通用服务错误，执行同样的验证码恢复，避免旧 token 残留。
- 成功：使用服务端返回的账号与 HttpOnly Cookie，保持现有课程选择和页面刷新逻辑，不额外 reset。

## 验证计划

1. 新增前端测试：认证失败时对外部提交回调返回 rejected，断言 token 失效并触发 Turnstile reset；表单字段仍在 DOM 中。
2. 新增后端测试：默认配置从不同当前工作目录创建时，默认 SQLite 路径仍指向 `apps/api/education.db`；显式数据库 URL 不被覆盖。
3. 运行 RED 测试确认失败原因是缺少目标行为。
4. 实现最小修复，运行目标测试确认 GREEN。
5. 运行 `pnpm check`、`pnpm build`，以及后端认证/验证码专项 pytest；必要时启动隔离 API，对注册、退出、历史账号大小写登录和验证码失败后的再次登录进行请求级验证。
