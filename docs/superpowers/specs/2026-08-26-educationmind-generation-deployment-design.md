# EducationMind 正式导入包与 AI 教官生成中心设计

## 1. 目标

本轮把 EducationMind 从“固定课程演示 + 手工命题 + Markdown 模板资源”升级为可导入其他平台的无登录教育智能体页面，并完成以下闭环：

- 昔涟以“AI 教官”而不是泛化陪伴助手的身份组织讲解、追问、练习和反馈。
- 学生未主动选择或开始学习前，不显示伪造的默认学习进度、默认任务或默认成绩。
- 教官可以按课程知识点生成整张试卷，题目进入正式题库，试卷进入既有发布、作答、评分和画像链路。
- 教官可以生成专项练习，学生作答后自动判卷；客观题与关键词题确定性评分，AI 语义题由外部 LLM 按受控评分量规判卷。
- 资源中心可以生成可下载的真实 PPTX，而非只输出 Markdown。
- 知识页面可以生成课程知识图谱，展示节点、关系、来源和生成模式。
- 使用用户提供的昔涟图片作为浏览器图标和应用品牌头像，原图不做生成式重绘。
- 交付平台静态导入 ZIP 和完整 Windows 部署 ZIP，两者必须明确能力边界并经过解压验证。

## 2. 设计决策与备选方案

### 方案 A：新建独立的 AI 生成、练习和资源系统

优点是短期文件之间干扰少；缺点是生成题不会进入已有题库，练习成绩不会自动进入考试分析和学生画像，会形成第二套不一致的数据模型。拒绝。

### 方案 B：仅在浏览器端生成静态内容

优点是容易打成纯静态 ZIP；缺点是 API 密钥会泄露，考试答案和评分规则暴露给学生，PPT/知识图谱不能形成服务器可追溯记录，也无法复用现有学习证据。拒绝。

### 方案 C：复用现有考试与知识领域，增加受控生成服务

生成服务只负责把课程材料和用户参数变成经过校验的题目、试卷、幻灯片大纲与图谱；考试发布、作答、判卷、成绩、学习证据继续走原有领域服务。外部 LLM 可用时使用受控 JSON 契约；不可用时使用课程材料驱动的确定性生成，并在结果中显式标注 `course_grounded`。采用此方案。

## 3. AI 教官体验

昔涟统一称为“昔涟教官”或“AI 教官”。系统提示词要求每次教学回答尽量按照以下结构组织：

1. 本次目标；
2. 核心讲解；
3. 检查理解的问题；
4. 下一步行动。

教官仍必须遵守课程知识与学习证据边界。未配置外部 LLM 时，回答继续使用明确标注的课程材料兜底，不得伪装为 AI 生成。

首页和学习空间不再把操作系统课程的固定模块、掌握度或任务呈现为学生已经开始的学习。内置操作系统材料继续作为可选择的课程资源，但空档案首先呈现“选择目标 / 生成诊断题 / 向教官提问”的入口。

## 4. 考试与练习生成

### 4.1 生成请求

`POST /api/exams/generate` 接收：

- `course_id`
- `knowledge_point_ids`，1 到 5 个
- `purpose`：`exam` 或 `practice`
- `title`
- `question_count`，3 到 30
- `difficulty`，0 到 1
- `duration_minutes`
- `publish_immediately`
- `include_ai_review_question`

后端只从课程知识仓库读取材料。外部 LLM 可用时，要求输出严格 JSON；服务端重新校验题型、选项、答案、关键词、解析、知识点和分值，不接受模型返回的任意数据库 ID 或代码。

### 4.2 生成结果

生成的每道题通过 `ExamService.create_question()` 入库，生成的试卷通过 `ExamService.create_exam()` 入库。练习默认立即发布；考试默认保留为草稿，由教官核对后发布。响应包含：

- 正式 `ExamOut`
- `generation_mode`：`llm` 或 `course_grounded`
- `provider` / `model`
- `source_sections`
- `warnings`

### 4.3 AI 自动判卷

新增内置题型“AI 语义简答题”，评分策略为 `ai_semantic`。交卷时先完成确定性题评分，再由 AI 评分器读取题目、参考答案、评分要点、学生答案和满分，要求返回严格 JSON：

```json
{"score_ratio": 0.8, "is_correct": false, "feedback": "解释了互斥，但缺少请求与保持条件"}
```

服务端将比例限制在 0 到 1，反馈限制长度并写入正式答案记录。LLM 不可用或输出无效时，降级到关键词比例评分，状态标记为 `auto_fallback`，反馈明确说明使用课程要点评分。不会把失败答案送入人工队列冒充“AI 已判卷”。

## 5. PPT 资源生成

资源类型增加 `presentation`。API 返回结构化幻灯片大纲，包括标题页、学习目标、核心概念、逐章节要点、课堂检查、总结与来源页。内容来自课程材料；LLM 可用时只允许在材料范围内重组表达。

浏览器使用 PptxGenJS 将结构化大纲导出为真正的 `.pptx`：

- 16:9 页面；
- 昔涟粉紫与星海视觉系统；
- 每页标题、要点、页码和来源；
- 不把 Markdown 文件改扩展名伪装为 PPTX；
- 导出失败时保留可阅读预览并显示错误。

已有学习单、闪卡、学习计划等类型继续保留，但统一显示来源和生成模式。

## 6. 知识图谱生成

新增 `GET /api/knowledge/graph?course_id=...`。图谱包含：

- 课程根节点；
- 知识点节点；
- 章节节点；
- `contains`、`explains` 和材料顺序推导的 `precedes` 关系；
- 每个节点和关系的来源章节；
- `generation_mode=course_grounded`。

前端知识页新增可缩放 SVG 图谱，节点可点击查看状态、来源和关系。学生画像的掌握度只装饰知识点节点，不改变课程关系；未评估仍不等于薄弱。

## 7. 图片与品牌资产

用户提供的 `G:\照片以及视频\照片\昔涟.jpeg` 作为原始品牌图标导入 `public/brand/cyrene-icon.jpeg`。页面通过 CSS 圆角裁切使用，浏览器 favicon 使用同一 JPEG。保留原图，不通过生成式图像工具重绘角色，不覆盖 Live2D 模型。

语音页面和部署文档继续保留以下文字：

> GPT-SOVITS项目作者为花儿不哭，推理包作者为红血球AE3803和白菜工厂1145号员工，自练作者为KearDawn

## 8. 正式部署目录和 ZIP

生成两个相互独立的交付物：

### 8.1 `EducationMind-Platform-Web-<version>.zip`

只包含构建后的 `dist` 根文件，不带 `./` 前缀和额外父目录，适合平台静态 ZIP 导入。包含 Live2D 和品牌图标。默认同源请求 `/api`。README 明确说明：平台若只托管静态文件，必须另行提供可公开访问的 API，纯静态导入不能运行考试、AI、网络搜索、数据库和 TTS。

### 8.2 `EducationMind-Windows-Full-<version>.zip`

包含：

- 前端 `dist`；
- API 源码、`pyproject.toml`、`uv.lock`；
- 生产启动和健康检查脚本；
- Genie-TTS 运行所需的模型、GenieData、参考音频和归属说明；
- 空白正式数据库初始化位置，不包含当前开发数据库；
- `.env.example`，只含变量名和安全占位符；
- 部署 README 和文件映射清单。

不包含 `node_modules`、开发日志、缓存、测试数据库、密钥、当前用户学习记录和用户未纳入范围的 DOCX。

ZIP 使用 .NET `ZipArchive` 创建并验证：文件数量、SHA-256、成员相对路径、无绝对路径、无 `..`、可由 `Expand-Archive` 解压。

## 9. 错误处理与安全

- LLM 输出必须经过 Pydantic/领域校验，失败不得写入半张试卷。
- 生成流程在单个数据库事务或显式回滚边界内完成。
- 学生作答接口永远不在交卷前返回正确答案。
- 公网无登录模式不授予命题权限保证；部署文档要求宿主平台限制命题 API、设置限流和配额。
- PPT 文件名净化，浏览器对象 URL 使用后立即释放。
- 图谱不执行任意脚本或表达式。
- 完整部署包中的模型和参考音频只供服务端读取，静态根目录只指向 `dist`。

## 10. 验收标准

- 后端单元/API 测试覆盖整卷生成、课程材料降级、AI JSON 校验、AI 判卷降级、PPT 大纲和知识图谱。
- 前端测试覆盖生成表单、真实考试创建后的刷新、PPTX 导出、知识图谱节点/关系、空学习档案和教官文案。
- `pnpm check`、前端测试、API 全量测试、`pnpm build` 全部通过。
- 浏览器实测 `/#/agent`、`/#/exams`、`/#/resources`、`/#/knowledge`，验证图标、Live2D、生成流程和下载。
- 两个 ZIP 均完成原生解压检查、文件清单检查和 SHA-256 计算。
- 最终报告区分源代码实现、构建产物、运行时 API、浏览器体验和 ZIP 工件，不把静态 ZIP 描述为完整后端部署。
