## 学习目标

- heap-invariant：区分完全二叉树形状与最大堆/最小堆序关系。
- heap-array-index：在固定的数组下标约定下计算父子索引。
- heap-operations：手工推演插入上滤、删除堆顶下滤。
- heap-build-sort：解释自底向上建堆的线性成本，并比较堆排序边界。

## 形状与堆序

二叉堆是完全二叉树：除最后一层外各层填满，最后一层从左向右连续排列。最大堆要求每个父结点键不小于其孩子；最小堆要求父结点键不大于其孩子。该不变量不保证兄弟结点有序，也不保证数组从头到尾排序。

采用 0 起始数组时，索引 i 的父结点为 floor((i−1)/2)，左孩子为 2i+1，右孩子为 2i+2；根没有父结点。采用 1 起始数组时公式不同，题目必须先声明索引约定。

## 插入与删除

插入先把新元素追加到数组末尾以保持完全树形状，再向上滤：只要它违反父子堆序，就与父结点交换。删除堆顶时用末尾元素填根并移除末尾槽，再向下滤；每次在违反堆序的孩子中选优先级更高者交换。堆高为 Θ(log n)，故插入与删除为 O(log n)，读取堆顶为 O(1)。

### 例一：最大堆插入

初始数组 [40,30,35,10,20] 是 0 起始最大堆。插入 50 后追加为 [40,30,35,10,20,50]；索引 5 的父索引为 2，交换得 [40,30,50,10,20,35]；再与索引 0 的 40 交换，得 [50,30,40,10,20,35]。最多沿树高交换 Θ(log n) 次。

### 例二：自底向上建堆

对 [3,1,6,5,2,4] 建最大堆，从最后一个非叶子索引 floor(n/2)−1=2 向前下滤。索引 2 的 6 大于孩子 4；索引 1 的 1 与较大孩子 5 交换；根 3 与较大孩子 6 交换后，再与孩子 4 交换。结果 [6,5,4,1,2,3] 满足最大堆序。

## 建堆、优先队列与排序成本

自底向上建堆从最后一个非叶子处理到根。虽然单次下滤最坏 O(log n)，低层结点很多但高度很小，把各层实际移动量相加为 Θ(n)，不能据此把它误写成必然 Θ(n log n)。逐个插入 n 个元素的上界则是 O(n log n)。

| 操作 | 复杂度 | 条件 |
| --- | --- | --- |
| peek 堆顶 | O(1) | 只读取根 |
| push 插入 | O(log n) | 追加后上滤 |
| pop 堆顶 | O(log n) | 末项补根后下滤 |
| bottom-up buildHeap | Θ(n) | 自底向上调整 |
| 堆排序 | Θ(n log n) | 常见原地实现辅助空间 O(1)，不稳定 |

堆适用于反复取得当前最小/最大优先级的任务队列。若业务需要按关键字完整有序遍历，堆序本身不足以提供这种次序。

## 常见误解与边界

- 最大堆根是最大值，但任意两片不同子树之间没有整体排序关系。
- 堆的完全树形状与堆序是两个同时成立、含义不同的不变量。
- 建堆的 O(n) 结论针对自底向上算法；不能直接套到逐个插入。
- 堆排序交换会跨越相等键，标准堆排序不稳定。
- 1 起始和 0 起始下标公式不能混用。

## 自测提示

对每次交换同时检查树形是否仍完全以及父子序是否恢复。计算复杂度时区分建堆、单次 push/pop 和连续排序。给出两个同层结点时，不要额外假定它们有序。
