## 学习目标

- recursion-termination：写出有效基例并保证规模向基例严格变化。
- recursion-trace：按调用与返回顺序推演递归状态。
- recursion-recurrence：从子问题数、规模和每层工作建立成本递推。
- recursion-space：按最大同时活动调用数估算辅助栈。

## 递归过程的结构

递归函数将问题化为更小的同类问题。一个正确的递归说明应明确输入范围、基例、递归子问题、子问题如何组成结果，以及规模为何逐步逼近基例。只写“函数调用自己”不能证明终止。

### 例一：阶乘的调用和返回

对 n≥0 定义 f(0)=1，n>0 时 f(n)=n·f(n−1)。计算 f(4) 时依次调用 f(3)、f(2)、f(1)、f(0)；到基例返回 1，再逆序得到 f(1)=1、f(2)=2、f(3)=6、f(4)=24。最多挂起 n+1 个常数大小调用帧，时间 Θ(n)，辅助栈 Θ(n)。

如果调用者允许负数，n−1 将一直远离 0；应在函数入口拒绝负输入或另行定义其行为。递归和循环在结果上可以相同，但调用栈成本不同。

## 递推与分治

对长度 n 的分治算法，T(n) 应反映子问题数量、每个子问题规模和拆分/合并工作。例：归并排序两个 n/2 子问题并线性合并，T(n)=2T(n/2)+Θ(n)=Θ(n log n)。只有说明子问题规模和每层工作后，才能解递推。

### 例二：递归树估算归并排序

规模 n 的根层合并 n 项；下一层有 2 个规模 n/2 的子问题，总合并量仍是 n；每继续一层，总工作仍 Θ(n)。把问题减到常数规模需要 Θ(log n) 层，因此总时间 Θ(n log n)。临时合并数组需要 Θ(n) 辅助空间，递归深度 Θ(log n)，总辅助空间仍由数组主导为 Θ(n)。

### 例三：两种 Fibonacci 实现

朴素递归 fib(n)=fib(n−1)+fib(n−2) 会重复求解相同参数，递归树规模随 n 指数增长。保存已算结果的记忆化版本只计算 0 到 n 的每个状态一次，时间 Θ(n)，同时保存 Θ(n) 个结果。不能只因每层参数减小，就断言总时间为 Θ(n)。

## 时间与空间成本

| 过程 | 时间 | 辅助空间 | 说明 |
| --- | --- | --- | --- |
| 逐项递归遍历 n 个结点 | Θ(n) | Θ(d) | d 是最大同时未返回的调用深度 |
| 归并排序 | Θ(n log n) | Θ(n) | 临时合并数组主导空间 |
| 朴素递归 Fibonacci | 指数级 | Θ(n) | 不缓存重叠子问题 |
| 记忆化 Fibonacci | Θ(n) | Θ(n) | 每个状态只求一次 |

尾递归描述的是递归调用位于函数尾部；除非运行环境明确承诺尾调用优化，不能据此把栈空间写成 O(1)。

## 常见误解与边界

- 基例只处理 n=0 时，必须限定输入 n≥0；负输入可能永远到不了基例。
- 递归调用总数、运行时间和同时活动调用栈深度不是同一个量。
- 递推式不能省略分支数和每层合并工作；“用了递归”本身没有固定复杂度。
- 记忆化会改变重复子问题的工作量，也会新增保存结果的空间。
- 尾递归的源代码形状不等于执行环境一定复用栈帧。

## 自测提示

对一个小输入，先画调用树，再标记返回顺序。对分治算法写出 T(n)=aT(n/b)+f(n)，并单独数递归深度和辅助存储。对递归基例检查输入域是否覆盖负值、空值和单元素情况。
