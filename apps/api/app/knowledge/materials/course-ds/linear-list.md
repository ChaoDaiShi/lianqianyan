## 学习目标

- linear-adt-storage：区分逻辑次序与物理存储表示。
- linear-array-cost：按长度、容量和位置计算顺序表操作成本。
- linear-insertion-cost：拆分链表定位成本与已知前驱后的链接修改成本。
- linear-list-variants：比较单链表、双向链表、循环链表和哨兵结点的边界。

## 定义与操作模型

线性表是有序元素序列；这里的“有序”指每个元素有确定位置，不表示元素值已经从小到大排列。ADT 可提供按位访问、按值查找、插入、删除和遍历等操作，具体复杂度由表示方式和题目给定的信息决定。

顺序表把元素放在连续存储位置。假定元素可等长随机访问，按下标读取 Θ(1)。向中间插入或删除，为保持连续性要移动后续元素，最坏 Θ(n)。动态数组尾部追加若没有触发扩容为 Θ(1)，触发几何扩容的一次可能搬移 Θ(n)，跨操作序列摊还 O(1)。

### 例一：顺序表在第 i 位前插入

长度 n=8，采用 1 起始位序，在第 3 位前插入。原第 3 至第 8 位共 6 项，必须从末尾向右移动，再写入新值；移动 6 项，渐进成本 Θ(n)。若是在末尾追加且有空容量，则无需移动已有项。

## 链表、定位与指针修改

单链表结点保存数据和 next 链接。按位查找必须从头逐个前进；链表不支持根据下标直接计算结点地址。已知前驱 p 后在 p 后插入新结点只需常数次链接修改。但“给头指针，插在第 i 位”包含先找前驱的扫描，整体最坏 Θ(n)。

“在已知结点 x 之前插入”是另一个问题：标准单链表结点没有 prev 链接，若未给 x 的前驱，就需从头查找；若题目改成“在 x 之后插入”，则 x 本身就是前驱，指针修改为 Θ(1)。不使用复制 x 数据来绕开前驱条件。

### 例二：同样插入，不同的给定条件

给定单链表头指针与目标值，要求在结点 X 之前插入：先扫描到 X 的前一结点，最坏 Θ(n)，再改链接 Θ(1)，总成本 Θ(n)。若直接给出前驱 p 并要求在 p 后插入，不需搜索，总成本 Θ(1)。题目中“位置是否已知”是复杂度的一部分。

双向链表结点另存 prev，可从已知结点沿前后方向访问。若给定一个非哨兵结点且其邻接结点可直接访问，删除该结点只需改相邻链接，Θ(1)；若只给关键字，还要计入查找成本。循环链表用尾结点链接回首结点，遍历应在再次回到起始结点时结束，而不是等待 null。

哨兵/头结点用于统一边界处理，不自动降低按值查找成本。空表、首结点插入和删除首结点的更新规则仍要按所采用的具体哨兵约定描述。

## 成本对照

| 操作 | 顺序表 | 单链表 | 说明 |
| --- | --- | --- | --- |
| 按下标读取 | Θ(1) | Θ(n) | 假定数组位置合法 |
| 按值查找 | Θ(n) | Θ(n) | 未排序时都可能扫完整表 |
| 中间插入 | Θ(n) | 定位后 Θ(1)，总计通常 Θ(n) | 链表必须说明前驱是否已知 |
| 头部插入 | Θ(n) | Θ(1) | 顺序表要腾位置 |
| 给定结点删除 | Θ(n) | 单链表需前驱；双链表 Θ(1) | 查找和修改要分开计 |
| 尾部追加 | 有空容量 Θ(1) | 有尾指针 Θ(1) | 动态数组单次扩容可能 Θ(n) |

链表多存指针，顺序表可能预留容量；“存储密度为 1”只适用于不计容量余量和管理元数据的教材模型。顺序表常有更好的连续访问局部性；链表也并非在所有频繁插删场景都更快，因为必须计入定位时间。

## 常见误解与边界

- “链表插入 O(1)”仅能描述已知前驱后的链接修改，不能省略定位步骤。
- 双向链表给定结点删除是 O(1)，不代表按值删除也是 O(1)。
- 循环链表不会在尾部遇到 null；需要用回到起点或访问计数控制遍历。
- 顺序表中间删除后仍需移动元素；表未满也不改变连续性要求。
- 复杂度要说明是否按 0 起始下标还是 1 起始位序计算移动个数。

## 自测提示

分别解答“在 x 后插入”和“在 x 前插入但没有前驱”两题。对每一步标注是否要搜索、是否要搬移、是否只改有限条指针；最后才合并成总复杂度。
