## 学习目标

- complexity-adt-model：把抽象数据类型规定的语义，与数组、链表等具体实现分开分析。
- complexity-growth-bounds：从输入规模和基本操作推导 O、Ω、Θ 渐进界。
- complexity-cases：分清最好、最坏、平均与摊还分析所使用的条件。
- complexity-space：区分输入空间和辅助空间，并按最大同时活动调用数计算栈空间。

## ADT、表示与计费模型

ADT 说明有哪些操作以及操作含义，例如集合的插入、查找和删除；它不规定元素必须存在哪种内存结构。数组表、链表或散列表是实现选择，成本要按所选表示和题目给出的操作来算。

复杂度分析先说明输入规模，例如数组长度 n、图的顶点数 V 和边数 E。再声明计费的基本操作，例如一次键比较、一次指针访问或一次边扫描。比较两个算法时应使用同一种模型；只凭代码行更少不能推出更快。

## 渐进记号与情形

对非负成本函数 f(n) 和充分大的 n，O(g(n)) 表示 f 的渐进上界，Ω(g(n)) 表示渐进下界，Θ(g(n)) 表示同时具有 O(g(n)) 与 Ω(g(n)) 界。O(n²) 可以是有效上界，即使算法实际是 Θ(n)；只有在上、下界同阶时才写 Θ。

最好、最坏和平均情形描述不同输入或分布。平均成本必须说明平均所依据的分布；不能把“平均”自动解释成概率期望，也不能从一个输入样例推出平均界。摊还分析则把一串操作的总成本分摊到每个操作；它不表示单次最坏成本，也不假设随机输入。

## 从代码计数

顺序语句的成本相加；嵌套循环要数清每个基本操作执行次数；依次减半或翻倍的循环通常执行 Θ(log n) 次。舍弃常数因子和低阶项只在渐进比较中成立，具体小 n 的实际运行时间仍可能受常数、缓存和实现影响。

### 例一：三角循环与倍增循环

执行 for i = 1..n，并在第 i 轮执行 i 次常数工作，总次数为 1+2+…+n=n(n+1)/2，因此是 Θ(n²)。若每轮把 j 乘以 2，j 从 1 长到 n，内层次数是 Θ(log n)；与外层 n 次相乘得到 Θ(n log n)。

### 例二：二分查找的循环次数

长度为 n 的已排序数组中，二分查找每一步最多保留约一半候选元素。经过 k 步后候选数至多约 n/2^k；令它小于 1，得 k=Θ(log n)。这只说明迭代比较次数；若用递归实现，调用栈另占 Θ(log n) 辅助空间。

## 摊还成本与空间成本

动态数组容量满时扩容并搬移元素，单次扩容追加可能是 Θ(n)。若容量每次至少翻倍，则连续 n 次追加总搬移量小于 2n 的常数倍，因此每次追加摊还 O(1)。不能把这个结论写成“每次追加最坏 O(1)”。

辅助空间不计输入本身。递归过程最多同时挂起 d 个常数大小调用帧时，辅助栈空间为 Θ(d)；归并排序除递归栈外还需 Θ(n) 临时数组，故总辅助空间为 Θ(n)。

## 复杂度速查

| 操作或算法 | 典型成本 | 必要条件或说明 |
| --- | --- | --- |
| 顺序表按下标访问 | Θ(1) | 下标合法、支持随机访问 |
| 未排序表线性查找 | 最坏 Θ(n) | 平均界还需说明目标分布 |
| 有序数组二分查找 | Θ(log n) | 关键字有序且能访问中点 |
| 比较排序下界 | Ω(n log n) | 适用于一般比较模型；不限制键范围的线性排序 |
| 递归调用栈 | Θ(d) | d 为最大调用深度，不是总调用次数 |
| 动态数组追加 | 摊还 O(1)，单次最坏 Θ(n) | 几何扩容策略 |

## 常见误解与边界

- “算法是 O(n²)”不等于它恰好做 n² 次操作；若要给紧确阶，应给出 Θ。
- 平均情形没有输入概率模型时不完整；摊还情形没有操作序列时也不完整。
- 快速程序不一定有更好的渐进阶；渐进界不承诺机器上的实际秒数。
- 图算法要同时报告 V、E；把 E 当作唯一规模会漏掉孤立顶点成本。
- 递归总调用次数与最大栈深度是两种不同指标。

## 自测提示

给定一段循环代码时，先写出基本操作的求和式再化简。给定一个递归式时，画出至少两层子问题规模。分别写出单次最坏成本、平均成本和摊还成本各自依赖的前提。
