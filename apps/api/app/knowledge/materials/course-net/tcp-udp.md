## 传输层的职责

传输层为运行在不同主机上的进程提供端到端通信，靠端口号区分同一主机上的多个应用。端口范围 0 到 65535：0 到 1023 是知名端口（HTTP 80、HTTPS 443、FTP 21、SMTP 25、DNS 53），1024 到 49151 是注册端口，其余为动态端口。传输层同时提供复用（多个应用共用网络接口）与分用（按端口号交付）能力。

## UDP 的特点

UDP 只在 IP 之上增加端口复用和差错检测，是无连接、不可靠、面向报文的传输方式。它不建立连接、不确认、不重传、不保证有序，头部只有 8 字节（源端口、目的端口、长度、校验和）。正因为开销小、延迟低，UDP 适合 DNS 查询、DHCP、流媒体、语音视频等允许少量丢包但要求实时的场景，也适合一次只交换少量数据的请求应答。

## TCP 的特点

TCP 是面向连接的可靠传输协议，通过确认与超时重传保证不丢、通过序号保证有序、通过校验和保证无差错，并提供流量控制与拥塞控制。TCP 面向字节流，没有消息边界，头部固定 20 字节，重要字段包括序号、确认号、窗口（用于流量控制）和六个控制位（SYN、ACK、FIN、RST、PSH、URG）。可靠性的代价是握手、确认和重传带来的延迟与开销。

## 三次握手与四次挥手

建立连接需要三次握手：客户端发 SYN，服务器回 SYN+ACK，客户端再回 ACK。三次的原因是双方都要确认自己的发送与接收能力正常，同时同步初始序号，两次握手无法防止失效的历史连接请求突然到达造成的资源浪费。释放连接需要四次挥手：主动方发 FIN，对方 ACK；对方数据发完再发 FIN，主动方 ACK。主动方最后进入 TIME_WAIT 状态等待 2MSL，保证最后的 ACK 丢失时可以重发，并让旧连接的报文在网络中消失。

## 流量控制、拥塞控制与自测

流量控制用滑动窗口防止接收方被淹没：接收方在确认中通告剩余缓冲区大小。拥塞控制防止网络过载，包含慢开始（指数增长）、拥塞避免（线性加一）、快重传（三个重复确认立即重发）和快恢复。常见误区有：认为 TCP 一定比 UDP"慢"（长传大文件时 TCP 反而合适）；把三次握手说成"请求-应答-数据"。自测应能回答：三次握手各报文的标志位；为什么挥手要四次；DNS 为什么用 UDP；慢开始与拥塞避免的门限关系。
