# Skill 能力契约参考

本文档是 `skills-manifest.json` 的补充，详细列出每个子 Skill 的能力契约。主 Skill 依据此契约调度。

---

## task-executor（任务执行）

| 字段 | 内容 |
|------|------|
| Skill ID | task-executor |
| 触发方式 | orchestrated |
| 职责 | 直接执行任务，输出最终成果 |
| 适用 | 明确的修改、生成、修复、润色、Debug、重构 |
| 不适用 | 需深度审查分析的任务 |
| 必要输入 | 待处理的内容 + 明确的处理意图 |
| 标准输出 | 可直接使用的最终成果 |
| 完成条件 | 成果可直接使用，无需再加工 |
| 失败回退 | 不确定时基于合理假设执行，输出可预览版本 |

## document-workflow（长文档工作流）

| 字段 | 内容 |
|------|------|
| Skill ID | document-workflow |
| 触发方式 | orchestrated |
| 职责 | 扫描、审查、修正超过 5 页的长文档 |
| 适用 | 论文、技术文档、报告、合同 |
| 不适用 | 短文档（<5 页）、纯翻译 |
| 必要输入 | 可读取的文档正文 |
| 标准输出 | 问题列表、修改建议、可直接替换的修正文本 |
| 完成条件 | 内容层检查完成；视觉层仅在有条件时执行 |
| 失败回退 | 无法完整读取时定位可读章节并明确缺失范围 |

## code-review（代码审查）

| 字段 | 内容 |
|------|------|
| Skill ID | code-review |
| 触发方式 | orchestrated |
| 职责 | 专业代码审查与诊断，输出修复方案（不直接修改代码） |
| 适用 | 代码片段、代码文件、代码项目的全面审查 |
| 不适用 | 纯架构讨论、技术选型建议 |
| 必要输入 | 可读取的代码 |
| 标准输出 | 诊断结果 + 修复方案 |
| 完成条件 | 静态审查完成，可确定的修复已诊断；无法运行时标注"未执行运行测试" |
| 失败回退 | 无法运行时声明"仅完成静态检查" |

## academic-review（论文评审）

| 字段 | 内容 |
|------|------|
| Skill ID | academic-review |
| 触发方式 | orchestrated |
| 职责 | 按正式学术标准审查论文 |
| 适用 | 学术论文、学位论文、会议投稿 |
| 不适用 | 仅翻译、仅格式转换 |
| 必要输入 | 可读取的论文正文 |
| 标准输出 | 问题定位、修改建议、可替换文本 |
| 完成条件 | 逻辑/数据/引用/格式/语言检查完成 |
| 失败回退 | 无法读取时定位可读部分并明确缺失范围 |

## project-workflow（项目工作流）

| 字段 | 内容 |
|------|------|
| Skill ID | project-workflow |
| 触发方式 | orchestrated |
| 职责 | 长期项目阶段管理与偏离检测 |
| 适用 | 毕设、课设、竞赛、创业项目、软件开发 |
| 不适用 | 单次任务、一次性咨询 |
| 必要输入 | 项目目标描述 |
| 标准输出 | 当前阶段、下一步、阻塞点 |
| 完成条件 | 阶段目标达成，有明确下一步 |
| 失败回退 | 信息不足时基于现有信息给出最佳判断 |

## socratic-tutor（苏格拉底式教学）

| 字段 | 内容 |
|------|------|
| Skill ID | socratic-tutor |
| 触发方式 | orchestrated |
| 职责 | 通过提问引导学生自主推导知识 |
| 适用 | 概念学习、问题理解、技能掌握 |
| 不适用 | 紧急任务、明确要求直接答案 |
| 必要输入 | 用户想学习的概念或问题 |
| 标准输出 | 引导性问题、调整后的一步、总结 |
| 完成条件 | 用户表达理解 |
| 失败回退 | 连续两轮无进展→切换为直接讲解 |

## deliverable-generator（智能交付）

| 字段 | 内容 |
|------|------|
| Skill ID | deliverable-generator |
| 触发方式 | orchestrated |
| 职责 | 判断回答是否应升级为独立成果文件 |
| 适用 | 回答可作为独立文档使用 |
| 不适用 | 一次性解释、简单确认 |
| 必要输入 | 已完成的分析结果或内容 |
| 标准输出 | 可直接使用的文件 |
| 完成条件 | 文件生成完毕 |

## qa-checker（质量检查）

| 字段 | 内容 |
|------|------|
| Skill ID | qa-checker |
| 触发方式 | always_final |
| 职责 | 所有最终输出的质量检查与自动修正 |
| 适用 | 所有最终输出 |
| 不适用 | 中间推理过程 |
| 必要输入 | 待输出的回复内容 |
| 标准输出 | 检查并修正后的最终回复 |
| 完成条件 | 6 项检查全部通过 |
| 失败回退 | 无法确认的项标记而非删除 |

## evidence-citation-guard（证据与引用守护）

| 字段 | 内容 |
|------|------|
| Skill ID | evidence-citation-guard |
| 触发方式 | conditional |
| 职责 | 保证事实、数据、引用和结论可追溯 |
| 适用 | 含引用/数据声称的论文、报告、分析 |
| 不适用 | 纯创意、纯观点 |
| 必要输入 | 待检查文本 + 用户原始材料 |
| 标准输出 | 标注证据等级的文本 |
| 完成条件 | 所有声称已分类标注 |
| 失败回退 | 无法确认的来源标记为"待核实"，仅当实际验证后才标记"已核实" |

## artifact-version-manager（成果版本管理）

| 字段 | 内容 |
|------|------|
| Skill ID | artifact-version-manager |
| 触发方式 | conditional |
| 职责 | 管理成果文件的版本、差异记录和回滚 |
| 适用 | 论文/PPT/代码的多轮迭代 |
| 不适用 | 一次性小修改 |
| 必要输入 | 待修改的成果文件 |
| 标准输出 | 新版本文件 + 变更摘要 |
| 完成条件 | 原版保留、新版生成、变更记录 |
| 失败回退 | 若平台不支持持久化，在项目目录保存 changelog；不声称已跨会话记住未实际保存的信息 |

## skill-creator（Skill 创建与优化）— scope: development

| 字段 | 内容 |
|------|------|
| Skill ID | skill-creator |
| 触发方式 | orchestrated |
| 职责 | 设计 Skill 目标、触发条件、能力契约和目录结构；调度 skill-developer 实现 |
| 适用 | 创建新 Skill、优化现有 Skill、评估 Skill 设计 |
| 不适用 | 直接在文件中编写内容（委托 skill-developer） |
| 必要输入 | Skill 意图描述或既有 Skill 文件 |
| 标准输出 | Skill 设计方案 + 测试用例 |
| 完成条件 | 设计确认、skill-developer 完成实现、静态校验通过 |
| 失败回退 | 无法确定触发条件时，基于最接近的已有 Skill 类比推断 |

## skill-developer（Skill 内容开发）— scope: development

| 字段 | 内容 |
|------|------|
| Skill ID | skill-developer |
| 触发方式 | orchestrated |
| 职责 | 在已有 Skill 模板上填充正文、编写脚本、补充参考文档、打磨 frontmatter |
| 适用 | 已有 SKILL.md 脚手架，需要填充内容 |
| 不适用 | 从零设计 Skill 目标与触发条件（委托 skill-creator） |
| 必要输入 | 已初始化的 Skill 目录 + 设计目标 |
| 标准输出 | 完整可用的 SKILL.md + 配套文件 |
| 完成条件 | frontmatter 完整、正文精简、脚本可执行且跨平台、无占位符 |
| 失败回退 | 缺失信息不影响整体方向→采用合理默认值；会改变核心职责/安全边界→只问一个关键问题 |
