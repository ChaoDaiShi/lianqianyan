# Artifact Version Manager（成果版本管理）

## 能力契约

| 字段 | 内容 |
|------|------|
| 职责 | 管理成果文件的版本、差异、回滚和状态追踪 |
| 适用场景 | 论文多轮修改、PPT 迭代、代码重构、长期项目 |
| 不适用场景 | 一次性小修改（如改一个变量名）、最终定稿后的归档 |
| 必要输入 | 待修改的成果文件路径或内容 |
| 标准输出 | 新版本文件 + 变更摘要 + 版本记录 |
| 完成条件 | 新版本已保存，原始版本已保留，变更已记录 |
| 失败回退 | 无法创建备份时明确告知用户并暂停覆盖 |
| 可组合 | 所有可能修改已有文件的 Skill |

---

## 版本操作规则

### 修改已有成果时（强制执行）

```
1. 保留原始版本 → 创建副本（如 foo_v1.md）
2. 生成新版本   → foo_v2.md
3. 记录本轮变化 → 变更摘要（改了什么、为什么）
4. 不破坏原文件 → 除非用户明确说"覆盖"/"替换"
```

### 版本命名

```
原始文件: thesis.md
v1 (原始): thesis.md（保持不变，或重命名为 thesis_v1.md）
v2 (修改): thesis_v2.md
变更摘要: thesis_changelog.md
```

### 回滚规则

发现修改方向错误时：
1. 不要基于错误版本继续堆叠修改
2. 回到最近一个稳定版本
3. 告知用户回退到了哪个版本及原因

---

## 项目状态追踪

对于长期项目，跨对话维护：

```
current_version: v3 (thesis_v3.md)
last_stable_version: v2 (thesis_v2.md)
change_summary: 第三章重写，修正统计口径
pending_decisions: [是否保留新增的对比实验]
```

---

## 输出规则

- 不向用户展示版本管理操作（如"已创建 v3 备份"）
- 只在回滚时简要说明："基于上一版 v2 继续修改"
- 变更摘要自然融入交付说明，不单独呈现
