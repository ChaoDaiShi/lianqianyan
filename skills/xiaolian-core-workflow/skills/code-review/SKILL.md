# Code Review（代码审查）

## 能力契约

| 字段 | 内容 |
|------|------|
| 职责 | 专业代码审查与诊断，输出修复方案 |
| 适用场景 | 代码片段、代码文件、代码项目的全面审查 |
| 不适用场景 | 纯架构设计讨论、技术选型建议（无代码） |
| 必要输入 | 可读取的代码 |
| 标准输出 | 诊断结果 + 修复方案 + 必要时完整项目 README |
| 完成条件 | 静态审查完成，可确定的修复已诊断；无法运行时标注"未执行运行测试" |
| 失败回退 | 无法实际运行时明确声明"仅完成静态检查" |
| 可组合 | task-executor（执行修复）, deliverable-generator, evidence-citation-guard |

## 触发条件

仅由 xiaolian-core-workflow 调度，或在用户明确点名本技能时使用。

## 审查维度（静默执行，不展示过程）

### 1. 正确性（最高优先级）
- 逻辑错误：条件判断、循环边界、变量作用域
- 边界条件：空数组、null/undefined、0、负数、极大值
- 错误处理：try-catch、异常返回、超时
- 类型安全：隐式转换、类型假设

### 2. 安全性
- 注入风险：SQL、命令、XSS、模板注入
- 敏感信息：硬编码密钥、Token、密码
- 权限/认证：缺少鉴权检查
- 依赖安全：已知漏洞的库版本

### 3. 性能
- 不必要的循环/递归
- 大对象/数组的引用传递
- 阻塞操作（同步 IO、长计算）
- 内存泄漏风险

### 4. 可维护性
- 函数/方法过长
- 深层嵌套
- 重复代码
- 魔法数字/硬编码
- 没有注释或注释过时

### 5. 命名与可读性
- 变量/函数/类名是否自解释
- 缩写是否在上下文中明确
- 命名风格是否一致

### 6. 工程结构
- 文件/模块划分是否合理
- 循环依赖
- import/require 的冗余
- 配置是否独立

## 输出规则

### 输出审查报告 + 修复方案
审查后输出：问题定位、严重程度、修复建议。不直接修改代码——实际代码修改由 task-executor 执行。

### 结构性问题
需重构架构或拆分文件的问题，不生成代码，仅指明方向。

### README 生成条件
仅当形成完整项目、存在依赖安装或运行步骤时才生成 README。不对小代码片段强制生成。

## 完成条件

静态审查完成，可确定的修复已诊断。若具备运行环境则可通过基本测试；若无法实际运行，**明确标注"未执行运行测试"**，不声称代码可运行。

不输出审查过程、不输出检查清单、不输出评分。
