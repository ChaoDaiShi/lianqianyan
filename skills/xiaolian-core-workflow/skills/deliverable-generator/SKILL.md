# Deliverable Generator（智能交付）

## 能力契约

| 字段 | 内容 |
|------|------|
| 职责 | 判断聊天回答是否应升级为可独立使用的成果文件 |
| 适用场景 | 回答可作为独立文档（论文、笔记、PPT、代码工程等） |
| 不适用场景 | 一次性解释、简单确认、临时建议 |
| 必要输入 | 已完成的分析结果或内容 |
| 标准输出 | Markdown/Word/PPT/代码工程等可直接使用的文件 |
| 完成条件 | 文件生成完毕，可直接使用 |
| 失败回退 | 无法生成特定格式时交付替代格式（如 PPTX→逐页大纲） |
| 可组合 | 所有执行类 Skill（作为交付环节） |

## 触发条件

当对话中产生的回答满足以下任一条件时，自动判断是否应升级为成果文件：

1. 回答本身可以作为独立文档使用
2. 回答比聊天上下文的寿命更长（值得保存）
3. 回答包含结构化内容（表格、图表、目录、章节）
4. 用户很可能需要把这个内容分享或存档

## 成果类型与判断标准

| 内容特征 | 应生成的成果 | 判断信号 |
|----------|-------------|----------|
| 长篇论述、论文、分析、总结 | Markdown / Word | 有标题层级、段落、结论 |
| 演示内容、汇报 | PPT / 幻灯片 | 有要点列表、需要视觉呈现 |
| 笔记、知识点整理 | Markdown / 学习笔记 | 有结构化的知识点 |
| 代码工程 | 代码文件 + README | 有多文件、可运行的代码 |
| 流程/架构描述 | 流程图 / 架构图 | 有步骤、关系、层级 |
| 数据对比/呈现 | 表格 / CSV / 图表 | 有多维度数据 |
| 时间线/进度 | 时间轴 | 有日期/阶段和时间点 |

## 核心判断：生成文件 vs 继续聊天

**生成文件的条件**：成果作为独立文件有价值——可以脱离聊天上下文被阅读、使用、分享。

**不生成文件的条件**：回答的价值仅存在于当前对话中（如一次性的解释、简单确认、临时的建议）。

## 生成规则

1. **直接生成，不询问。** 判断应生成时，直接生成并告知文件位置，不要说"要不要我把这个保存成文件？"。
2. **文件可直接使用。** 生成的 Markdown 有正确的格式、代码有正确的语法、表格有完整的数据。
3. **不为生成而生成。** 如果回答只有几行字，不要强行扩展成文件。
4. **如果内容很少却频繁生成无关文件，会引起用户反感。**

## 输出格式

生成文件后，输出简洁的提示：

```markdown
已将 [内容描述] 保存为 `[文件名]`，可以直接使用。
```

文件写入完成后，不对内容做二次文字描述（文件本身就是交付物）。
