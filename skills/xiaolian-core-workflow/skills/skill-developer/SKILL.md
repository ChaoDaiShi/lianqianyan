# Skill Developer（技能内容开发）

## 能力契约

| 字段 | 内容 |
|------|------|
| 职责 | 在已有 Skill 模板上填充正文、编写脚本、补充参考文档、打磨 frontmatter |
| 适用场景 | 已有 SKILL.md 脚手架，需要填充内容 |
| 不适用场景 | 从零设计 Skill 目标与触发条件（委托 skill-creator） |
| 必要输入 | 已初始化的 Skill 目录 + 设计目标 |
| 标准输出 | 完整可用的 SKILL.md + 配套文件 |
| 完成条件 | frontmatter 完整、正文精简、脚本可执行且跨平台、无占位符 |
| 失败回退 | 缺失信息不影响整体方向→采用合理默认值继续；缺失信息会改变核心职责/安全边界→只问一个关键问题 |
| 可组合 | skill-creator, qa-checker |

## 触发条件

仅由 xiaolian-core-workflow 调度，或在用户明确点名本技能时使用。

## 开发流程

### 1. 读取现有脚手架

列出工作目录，读取 SKILL.md 与 references/scripts/assets 下已有文件，理解模板现状。不重建脚手架，只在其上填充与扩展。

### 2. 明确技能目标

与用户或 skill-creator 确认：技能做什么、输入输出、何时被唤起。

> **原则**：缺失信息不影响整体方向时，采用合理默认值继续开发。只有缺失信息会改变 Skill 的核心职责、输入输出或安全边界时，才询问一个关键问题。这与主 Skill 的"减少确认、合理假设"一致。

### 3. 打磨 frontmatter

- **name**：kebab-case，与技能目录名一致。
- **description**：写清"做什么 + 何时使用 + 关键词"——这是技能被检索匹配的依据。
- **license**：按需填写，与项目整体许可证一致。
- 字段格式拿不准时，调用 skill-creator 核实。

### 4. 开发正文与内容

- **SKILL.md 正文**：面向执行的简明操作指南（建议 <500 行）。细节下沉到子文件。
- **scripts/**：确定性重逻辑。脚本须跨平台可执行——用 `os.path.join()` 而非硬编码路径分隔符，不依赖平台独有命令。
- **references/**：大段说明、示例、文档。
- **assets/**：静态数据、模板、配置。

### 5. 查证与试跑

- 涉及外部库、标准或陌生领域时，优先使用平台当前可用的官方文档检索、网页搜索或资料读取工具。
- 若平台没有可用检索工具，应明确标记"待核实"，不凭记忆编造。
- 在工作空间实际运行 scripts/ 验证可执行性。

### 6. 自检交付

核对：frontmatter 完整（name/description 非空）、正文精简、脚本可跑且跨平台兼容、命名一致、无模板占位符。

## 原则

- 只在已有模板上增量开发，不覆盖、不推倒重来
- 优先沉淀一手资料，而非凭记忆编造
- 不过度设计，只满足明确需求
- 确保脚本和路径在 macOS、Windows、Linux 上均可用
