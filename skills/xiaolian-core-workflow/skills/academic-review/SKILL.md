# Academic Review（论文评审）

## 能力契约

| 字段 | 内容 |
|------|------|
| 职责 | 按正式学术标准审查论文 |
| 适用场景 | 学术论文、学位论文、会议投稿的全面评审 |
| 不适用场景 | 仅翻译、仅格式转换、非学术文档 |
| 必要输入 | 可读取的论文正文 |
| 标准输出 | 问题定位、修改建议、可替换文本 |
| 完成条件 | 完成逻辑、数据、引用、格式和语言检查 |
| 失败回退 | 文档无法读取时定位可读部分并明确缺失范围 |
| 可组合 | Document Workflow, Evidence Guard, Deliverable Generator |

## 触发条件

仅由 xiaolian-core-workflow 调度，或在用户明确点名本技能时使用。

## 审查维度（静默执行）

### 1. 逻辑与论证
- 研究问题是否明确
- 假设是否合理
- 论证链条是否完整无断点
- 是否存在循环论证
- 结论是否有数据支撑

### 2. 数据与统计
- 样本量是否合理
- 统计方法是否正确
- 显著性/置信度是否恰当标注
- 数据是否有选择性报告嫌疑
- 实验是否可复现（方法描述充分性）

### 3. 图表与公式
- 图表是否清晰、标注完整
- 单位、轴标签、图例是否正确
- 公式编号是否连续、引用是否正确
- 符号定义是否前后一致

### 4. 引用
- 关键声明是否有文献支撑
- 引用是否为该领域权威或最新来源
- 引文格式是否统一（会议/期刊要求）
- 自引是否合理（不过度）

### 5. 结构与表达
- 摘要是否完整概括全文
- 章节编号是否连续、层级正确
- 章节间过渡是否自然
- 标题是否准确反映内容
- 语言是否清晰、无歧义、无过度华丽

### 6. 创新性
- 与已有工作的差异化是否明确
- 贡献（contribution）是否在 Introduction 中清晰列出
- 方法论是否有实质创新 or 仅仅是工程组合

## 输出规则

### 指出问题 + 给出修改
每个问题按以下格式：
```
**问题**：[具体是什么问题]
**位置**：[章节/段落/图表编号]
**建议**：[如何修改]
```

### 对可以自动修改的内容
直接输出修改后的版本（改写后的段落、修正后的图表标题、调整后的参考文献格式）。

### 优先级标记
- 🔴 致命问题：逻辑错误、数据矛盾、结论无支撑
- 🟡 重要问题：缺关键实验对比、引用不当、论证不足
- 🟢 小修：语言、格式、编号

## 输出格式

```markdown
## 论文评审意见

**论文**：[标题]

### 整体评价
[1-2 句]

### 主要问题

🔴 **[问题标题]**
**问题**：...
**位置**：...
**建议**：...
**修改后版本**（如适用）：
[直接修改后的内容]

### 修改优先级汇总
- 🔴 N 项必须修改
- 🟡 N 项建议修改
- 🟢 N 项可选
```

不输出审稿模板、不输出审稿流程描述、不解释审稿标准。
