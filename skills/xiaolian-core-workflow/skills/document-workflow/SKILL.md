# Document Workflow（长文档工作流）

## 能力契约

| 字段 | 内容 |
|------|------|
| 职责 | 扫描、审查、修正超过 5 页的长文档 |
| 适用场景 | 论文、技术文档、报告、合同等长文档审查 |
| 不适用场景 | 短文档（<5 页）、纯翻译请求 |
| 必要输入 | 可读取的文档正文 |
| 可选输入 | 审查重点（如"只看格式"） |
| 标准输出 | 问题列表、修改建议、可直接替换的修正文本 |
| 完成条件 | 内容层检查完成（结构/逻辑/数据/引用/编号/语言）；视觉层仅在有条件时执行 |
| 失败回退 | 文档无法完整读取时，定位可读章节并明确缺失范围 |
| 可组合 | academic-review, task-executor, deliverable-generator |

## 触发条件

仅由 xiaolian-core-workflow 调度，或在用户明确点名本技能时使用。

## 策略选择

| 文档体量 | 策略 |
|----------|------|
| 短文档（< 5 页） | 常规处理，不走本流程 |
| 中文档（5-20 页） | 快速扫描 + 重点定位 |
| 长文档（> 20 页） | 先扫描目录/标题结构，再决定全文或跳读 |

## 执行流程（静默执行，不展示）

### 1. 结构扫描
- 提取所有标题/章节编号
- 判断目录与实际标题是否对应
- 快速识别文档类型（论文 / 技术文档 / 报告 / 合同 / 其他）

### 2. 格式检查（内容层 — 始终执行）
- 标题编号：是否连续、层级正确、无跳号
- 列表：序号正确、缩进一致
- 引用格式是否统一

### 2b. 格式检查（视觉层 — 仅当具备视觉读取能力时执行）
- 字体/样式一致性
- 页眉页脚、页码连续性
- 图片清晰度
若仅获得纯文本，明确说明"已完成内容层审查，视觉层需在原始文档中人工确认"。

### 3. 逻辑检查
- 前后陈述是否矛盾
- 段落结构是否完整（有主题句、有展开、有结论）
- 章节间过渡是否自然

### 4. 数据一致性（论文/报告加强）
- 同一数据在多处是否一致
- 图表数据与正文描述是否对应
- 统计口径是否统一标注
- 总数与分量之和是否吻合

### 5. 引用检查（论文/报告加强）
- 正文引用是否在参考文献中列出
- 参考文献是否为正文引用
- 引用格式是否统一

### 6. 图表一致性（论文加强，仅视觉层可用时）
- 图表编号是否连续
- 图表标题格式是否一致

### 7. 代码文档专用
- API 签名与文档描述是否一致
- README 与代码实际行为是否一致
- 文件路径/结构描述是否正确
- 示例代码逻辑是否正确、可运行

## 输出格式

**直接输出结果，不展示检查过程。**

```markdown
## 文档审查结果

### 文档类型：[自动判断]
### 审查范围：[内容层 / 内容层 + 视觉层]

### 总体评价
[1-3 句概括]

### 发现的问题
1. [问题] → [建议]
2. [问题] → [建议]

### 修改建议优先级
- 🔴 必须改：[关键问题]
- 🟡 建议改：[改进建议]
- 🟢 可选：[锦上添花]

### 修改后版本（如适用）
[直接输出修改后的关键章节或全文]
```

如无问题，仅输出"未发现明显问题"。
